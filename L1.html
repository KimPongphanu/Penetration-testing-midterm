วิชา Penetration Testing and Protection (0406136051)

1. ความหมายของ Penetration Testing (Pen Test)

Penetration testing (pen testing) หรือที่รู้จักในชื่อ Ethical Hacking คือการใช้เทคนิคการโจมตีเพื่อวัตถุประสงค์ที่ถูกต้องและมีจริยธรรม เพื่อปรับปรุงความปลอดภัยของระบบ โดยเป็นกระบวนการจำลองการโจมตีระบบ เครือข่าย หรือแอปพลิเคชันอย่างได้รับอนุญาต เพื่อค้นหาและประเมิน ช่องโหว่ความปลอดภัยก่อนที่ผู้ไม่ประสงค์ดีจะใช้ประโยชน์ได้

การทดสอบเจาะระบบเป็นการทดสอบที่ประเมินจุดแข็งของมาตรการรักษาความปลอดภัยทั้งหมดบนระบบคอมพิวเตอร์ ทั้งในเชิงเทคโนโลยี (Technological Controls) เชิงขั้นตอน (Procedural Controls) และเชิงปฏิบัติการ (Operational Controls) โดยผู้เชี่ยวชาญจะจำลอง เทคนิคและวิธีการของแฮกเกอร์ในการพยายามเข้าถึงเครือข่ายหรือระบบสารสนเทศ

2. Penetration Tester (Pentester) คือใคร

  • ผู้เชี่ยวชาญด้านความปลอดภัยทางไซเบอร์ที่จำลองการโจมตีทางไซเบอร์ต่อระบบขององค์กร เพื่อระบุช่องโหว่
  • เป้าหมายคือช่วยให้องค์กรเข้าใจจุดอ่อนด้านความปลอดภัยของตน และวิธีบรรเทาความเสี่ยง (Mitigation)
  • Pen Tester ใช้เครื่องมือ เทคนิค และกระบวนการเดียวกับผู้โจมตีจริง เพื่อค้นหาและแสดงผลกระทบทางธุรกิจของจุดอ่อนในระบบ

3. ทำไม Penetration Testing ถึงสำคัญ (Why it is essential)

  • Uncover Hidden Weaknesses: ค้นพบจุดอ่อนที่ซ่อนอยู่ซึ่งการตั้งค่าที่ซับซ้อนอาจทำให้มองไม่เห็น
  • Improve Security Posture: ปรับปรุงแนวรับความปลอดภัยโดยการอุดช่องโหว่ (Patch Weaknesses)
  • Reduce Risk of Breaches: ลดความเสี่ยงของการถูกโจมตีที่ประสบความสำเร็จ
  • Compliance Requirements: หลายกฎหมายและมาตรฐานอุตสาหกรรมกำหนดให้องค์กรต้องทดสอบเจาะระบบเป็นประจำ เช่น PCI DSS และ HIPAA
  • Build Confidence: สร้างความเชื่อมั่นให้กับองค์กรและลูกค้า
  • Stay Ahead of Attackers: ก้าวล้ำหน้าผู้โจมตีด้วยการค้นหาช่องโหว่ก่อน

4. ประโยชน์ของ Penetration Testing (Benefits)

  • ช่วยระบุช่องโหว่ที่อาจไม่มีใครค้นพบ
  • ช่วยค้นพบภัยคุกคามใหม่ที่อาจมาจากผู้โจมตีหรือผู้บุกรุก
  • ช่วยระบุช่องโหว่แบบเรียลไทม์ภายในระบบและเว็บแอปพลิเคชัน
  • ช่วยทดสอบประสิทธิภาพของ Web Application Firewall (WAF)
  • ช่วยทดสอบความสามารถในการป้องกันทางไซเบอร์ขององค์กร
  • ช่วยระบุ Misconfigurations ที่ไม่ตั้งใจซึ่งอาจทำให้ระบบเสี่ยงต่อการถูกโจมตี
  • ช่วยหลีกเลี่ยงเหตุการณ์ที่สร้างความเสียหายทางการเงินและลดค่าใช้จ่ายจากการถูกโจมตี
  • ช่วยเพิ่มความตระหนักด้านความปลอดภัยให้กับพนักงาน (Security Awareness)
  • ช่วยให้ผู้เชี่ยวชาญด้านความปลอดภัยอัปเดตความรู้เกี่ยวกับภัยคุกคามและเทคนิคล่าสุดอยู่เสมอ

5. Penetration Testing กับ White Hat Hacking

  • Penetration Testing: มีโครงสร้างและกระบวนการที่ชัดเจน (Structured) ใช้เฟรมเวิร์กที่มีขั้นตอน เช่น Reconnaissance, Scanning, Exploitation และ Reporting เน้นระบบหรือเครือข่ายที่เฉพาะเจาะจง ให้ผลลัพธ์เป็นรายงานโดยละเอียด
  • White Hat Hacking: เป็นคำกว้างกว่า ครอบคลุมการใช้ทักษะแฮกกิ้งอย่างมีจริยธรรม อาจมีความสร้างสรรค์และยืดหยุ่นกว่า เช่น การใช้ Social Engineering หรือ Zero-day Exploits รวมถึงกิจกรรมการฝึกอบรมความปลอดภัยและการพัฒนาเครื่องมือป้องกัน

6. คำศัพท์ที่เกี่ยวข้อง (Terms)

  • Red Teaming: การทดสอบเจาะระบบรูปแบบพิเศษที่ผู้ทดสอบเป็นปฏิปักษ์กับองค์กร (Adversarial) พยายามเลียนแบบผู้โจมตีจริงและหลบเลี่ยงการตรวจจับ
  • Ethical Hacking: การแฮกโดยได้รับอนุญาตเพื่อปรับปรุงความปลอดภัย

7. Penetration Testing vs. Vulnerability Assessment

  • Vulnerability Assessment (VA): เน้นการสแกนค้นหาและระบุรายการช่องโหว่ทั้งหมดที่มีตามฐานข้อมูล (เน้นความกว้างของระบบ)
  • Penetration Testing (PT): เน้นการทดสอบเจาะระบบจริงผ่านช่องโหว่เพื่อยืนยันผลกระทบและการเข้าถึงระบบ (เน้นความลึกและพิสูจน์ผลลัพธ์)

8. รูปแบบการทดสอบ (Testing Methodologies)

  • Black Box: ผู้ทดสอบไม่มีข้อมูลภายในของระบบเป้าหมายมาก่อน (จำลองมุมมองแฮกเกอร์จากภายนอก) ในการทดสอบเครือข่ายจะไม่ทราบ DMZ, OS หรือ Server Version มีเพียงช่วง IP ที่ให้ทดสอบ
  • White Box: ผู้ทดสอบได้รับข้อมูลโครงสร้าง ซอร์สโค้ด หรือสถาปัตยกรรมระบบอย่างละเอียด เช่น ซอร์สโค้ดของเว็บแอปพลิเคชันเพื่อทำ Source Code Analysis
  • Gray Box: ผู้ทดสอบมีข้อมูลบางส่วน เช่น ได้รับบัญชีผู้ใช้ระดับทั่วไป

9. ขั้นตอนพื้นฐานของการทำ Pentest (Phases)

  • Reconnaissance / Information Gathering: การเก็บรวบรวมข้อมูลของเป้าหมาย
  • Scanning & Enumeration: การสแกนพอร์ตและแจกแจงรายละเอียดของบริการ
  • Vulnerability Assessment: การวิเคราะห์หาจุดอ่อนและช่องโหว่
  • Exploitation: การเจาะระบบจริงเพื่อยืนยันช่องโหว่
  • Post-Exploitation & Reporting: การคงสิทธิ์ การสำรวจระบบภายใน และการสรุปรายงานผลการทดสอบ

10. Rule of Engagement (ROE)

ก่อนเริ่มการทดสอบเจาะระบบ ต้องมีการจัดทำและอนุมัติ Rule of Engagement (ROE) อย่างเป็นทางการ ซึ่งประกอบด้วย ขอบเขตการทดสอบ ระยะเวลา วิธีการที่ใช้ เป้าหมาย ข้อจำกัดทางกฎหมาย และความรับผิดชอบของทั้งสองฝ่าย การทดสอบเจาะระบบ ต้องกระทำกับระบบที่ได้รับอนุญาตเท่านั้น

11. การเตรียม Lab Environment

  • Kali Linux: ระบบปฏิบัติการฝั่ง Attacker ที่รวบรวมเครื่องมือด้าน Information Gathering, Vulnerability Assessment, Exploitation, Password Attacks และ Wireless Attacks ไว้มากมาย
  • Metasploitable2: Virtual Machine ที่ตั้งใจให้มีช่องโหว่เพื่อฝึกฝนเทคนิคการเจาะระบบอย่างปลอดภัย
    • Metasploitable 1 (2010): เก่าและช่องโหว่หลายรายการใช้ไม่ได้แล้ว
    • Metasploitable 2 (2012): มีช่องโหว่เพิ่มมากขึ้น ใช้เป็นเป้าหมายหลักของรายวิชา
    • Metasploitable 3: เวอร์ชันล่าสุด เพิ่มสภาพแวดล้อม Windows เข้ามาฝึกด้วย
  • DVWA (Damn Vulnerable Web App): เว็บแอปพลิเคชันที่ตั้งใจให้มีช่องโหว่สำหรับฝึกฝน Web Security เช่น SQL Injection, XSS และการตั้งค่าที่ไม่ปลอดภัย
  • VirtualBox / VMware: ใช้ติดตั้ง Virtual Environment ให้เครื่อง Kali และ Metasploitable2 เชื่อมต่อกันได้ผ่าน Host-Only / Internal Network

12. แหล่งฝึกฝนเพิ่มเติม (Resources)

  • TryHackMe: https://tryhackme.com/ — แพลตฟอร์มเรียนรู้แบบ Gamified เหมาะกับผู้เริ่มต้น มีทั้งแบบฟรีและเสียเงิน
  • Hack The Box: https://www.hackthebox.com/ — แพลตฟอร์มยอดนิยมที่มีเครื่อง VM ให้ฝึกหลายร้อยเครื่องจำลองสถานการณ์จริง
  • PortSwigger / Burp Suite: https://portswigger.net/web-security — แหล่งเรียนรู้ Web Security
  • OverTheWire: https://overthewire.org/wargames/bandit/ — Wargaming challenges ฟรีสำหรับฝึกแนวคิด Penetration Testing
  • CTFLearn: https://ctflearn.com/lab/ — เรียนรู้ความปลอดภัยสารสนเทศผ่าน CTF challenges ฟรี
คำเตือนทางกฎหมาย: ให้แฮกเฉพาะระบบที่ได้รับอนุญาตเท่านั้น และควรมีหลักฐานเป็นลายลักษณ์อักษร การแฮกโดยไม่ได้รับอนุญาตเป็นสิ่งผิดกฎหมาย

13. สรุปภาระงาน / งานที่มอบหมาย (Assignment)

  • งานในคลาส: การติดตั้งและตั้งค่าระบบปฏิบัติการทดสอบ (Kali Linux และ Metasploitable2) ให้สามารถเชื่อมต่อเครือข่ายแล็บ (Host-Only / Internal Network) เพื่อให้สื่อสารระหว่างกันได้
  • การบ้าน/แบบฝึกหัด: ปูพื้นฐานแนวคิดและการเตรียมสภาพแวดล้อมแล็บเพื่อรองรับงานส่งจริงในบทเรียนถัดไป (Nmap / Vulnerability Assessment / Exploitation)
