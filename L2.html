สรุปเนื้อหาและปฏิบัติการ Lecture 2: Reconnaissance, Information Gathering & Linux Fundamentals

วิชา Penetration Testing and Protection (0406136051)

1. ประเภทของการทดสอบตามระดับความลึก (Types of Tests: Testing Depth)

ประเภท รายละเอียด
Vulnerability Scans เพียงแค่รัน Vulnerability Scanner (ยังไม่ใช่ Pentest)
Vulnerability Assessments Vulnerability Scanning + การตรวจสอบยืนยันช่องโหว่ (Validation) (ยังไม่ใช่ Pentest)
Pentest Vulnerability Assessment + Exploitation (การเจาะระบบจริง หรือที่เรียกว่า Hacking)
Red Team / Adversarial Tests ทดสอบ Blue Team จำลองการโจมตีจริง ขอบเขตที่ผ่อนปรนกว่า

2. ประเภทของ Penetration Testing (ตามเป้าหมาย)

  • Network Penetration Testing: ทดสอบในเครือข่ายขององค์กรเพื่อค้นหาจุดบกพร่องในการออกแบบ (Design) การทำงาน (Operation) หรือการนำไปใช้ (Implementation) ของเครือข่าย
  • Physical Penetration Testing: ผู้ทดสอบสวมบทบาทผู้โจมตีเพื่อพยายามฝ่าแนวป้องกันทางกายภาพ เช่น กล้องวงจรปิด ล็อกเกอร์ สิ่งกีดขวาง และเซนเซอร์
  • Web Application Penetration Testing: ตรวจหาช่องโหว่หรือจุดอ่อนภายในเว็บแอปพลิเคชัน
  • Wireless Network Penetration Testing: ตรวจสอบการเชื่อมต่อระหว่างอุปกรณ์ทั้งหมดที่เชื่อมต่อกับ Wi-Fi ขององค์กร

3. มาตรฐานและระเบียบวิธีทดสอบ (Methodology Standards)

ระเบียบวิธีทดสอบเจาะระบบให้แนวทางที่มีโครงสร้างสำหรับการประเมินความปลอดภัย แต่ละมาตรฐานมีจุดเน้น ขอบเขต และรายละเอียดที่แตกต่างกัน

มาตรฐาน รายละเอียด
OSSTMM Open Source Security Testing Methodology Manual — เน้นการวัดผลความปลอดภัยเชิงปฏิบัติการ (OpSec) มีหัวข้อ Operational Security Metrics, Trust Analysis, Work Flow, การทดสอบ Human/Physical/Wireless/Telecom/Data Networks และรายงานแบบ STAR (Security Test Audit Report)
OWASP Testing Guide พัฒนาโดย OWASP (องค์กรไม่แสวงหาผลกำไรด้าน Web Security) เน้นช่องโหว่ในเว็บแอปพลิเคชันและ API มีเฟสแบบยืดหยุ่น เช่น Reconnaissance, Enumeration, Exploitation, Reporting
NIST SP 800-115 คู่มือทางเทคนิคสำหรับการทดสอบความปลอดภัย แนะนำให้มีนโยบายประเมิน, ระเบียบวิธีที่ทำซ้ำได้และมีเอกสาร, กำหนดวัตถุประสงค์ และวิเคราะห์ผลเพื่อพัฒนาแนวทางลดความเสี่ยง
PTES Penetration Testing Execution Standard — เน้นทั้งด้านเทคนิคและบริบทธุรกิจ มี 7 เฟส: Pre-engagement, Intelligence Gathering, Threat Modeling, Vulnerability Analysis, Exploitation, Post Exploitation, Reporting
ISSAF Information System Security Assessment Framework — 9 ขั้นตอน: Information Gathering, Network Mapping, Vulnerability Identification, Penetration, Gaining Access & Privilege Escalation, Enumerating Further, Compromising Remote Users/Sites, Maintaining Access, Covering Tracks

4. ขั้นตอนร่วมของการทดสอบและ Pre-engagement

  • Pre-Engagement and Planning: กำหนดขอบเขต วัตถุประสงค์ และ Rule of Engagement ของการทดสอบ
  • Intelligence Gathering: เก็บข้อมูลเป้าหมาย เช่น โครงสร้างเครือข่าย ระบบปฏิบัติการ และแอปพลิเคชัน
  • Vulnerability Analysis & Exploitation: ระบุและใช้ประโยชน์จากช่องโหว่เพื่อประเมินผลกระทบ
  • Solution Development: แนะนำแนวทางแก้ไข (Remediation)
  • Report Drafting & Certificate Issuance: จัดทำรายงานและใบรับรอง
Pre-engagement: ก่อนเริ่มทดสอบ ลูกค้าและผู้ทดสอบต้องหารือเกี่ยวกับข้อกำหนดทางกฎหมายและกฎของการมีส่วนร่วม (Rules of Engagement) ซึ่งรวมถึงขอบเขต, วันที่เริ่ม/สิ้นสุด, เป้าหมาย, ระเบียบวิธี, ความรับผิดชอบ (Liabilities) และต้องได้รับความยินยอมร่วมกันก่อนเสมอ

5. Rules of Engagement (ROE)

ข้อกำหนดที่สำคัญซึ่งแทบทุก ROE จะต้องมี:

  • เอกสาร "Permission to hack" และ "Nondisclosure Agreement" ที่ลงนามโดยทั้งสองฝ่าย
  • ขอบเขตของการทดสอบ (Scope) และส่วนใดขององค์กรที่ต้องทดสอบ
  • ระยะเวลาโครงการรวมถึงวันเริ่มและวันสิ้นสุด
  • ระเบียบวิธี (Methodology) ที่ใช้ดำเนินการทดสอบเจาะระบบ
  • เป้าหมายของการทดสอบเจาะระบบ
  • เทคนิคที่อนุญาตและไม่อนุญาต เช่น ควรทดสอบ Denial-of-Service (DoS) หรือไม่
  • ความรับผิดชอบ (Liabilities) ที่ตกลงกันล่วงหน้า เช่น กรณีเข้าถึงข้อมูลอ่อนไหว (บัตรเครดิต) หรือทำให้ระบบหยุดทำงาน

6. Categories of Penetration Test (ตามข้อมูลที่ได้รับ)

  • Black Box: ให้ข้อมูลเกี่ยวกับเป้าหมายน้อยมากหรือแทบไม่มี เช่น ไม่รู้ DMZ, OS, Server Version มีเพียงช่วง IP ที่ให้ทดสอบ (เหมาะกับการทดสอบภายนอก External Test)
  • White Box: ให้ข้อมูลเกือบทั้งหมด เช่น เวอร์ชันแอปพลิเคชัน ระบบปฏิบัติการ และซอร์สโค้ด เพื่อทำ Static/Dynamic Source Code Analysis (พบมากในการทดสอบภายใน Internal/Onsite)
  • Gray Box: ให้ข้อมูลบางส่วน เช่น บัญชีผู้ใช้ระดับทั่วไป (ผสมระหว่าง Black และ White Box)

7. แนวคิดการเก็บข้อมูล (Information Gathering / Reconnaissance)

ผู้ทดสอบเจาะระบบจะเก็บรวบรวมข้อมูลเกี่ยวกับระบบเป้าหมาย เครือข่าย แอปพลิเคชัน หรือองค์กรอย่างเป็นระบบ เพื่อสร้างโปรไฟล์ที่ครอบคลุมของเป้าหมาย เข้าใจสถาปัตยกรรม และระบุช่องโหว่ที่อาจเกิดขึ้น ซึ่งเป็นรากฐานของแผนการโจมตีที่มีประสิทธิภาพ

คำศัพท์ ความหมาย
Information Gathering คำรวมสำหรับกิจกรรมการเก็บรวบรวมข้อมูลทั้งหมด (umbrella term)
Reconnaissance ภาพรวมเบื้องต้นขององค์กรเป้าหมาย เช่น ค้นหาเว็บไซต์, สื่อสังคมออนไลน์, IP Range, Domain Names, อีเมล และข้อมูล WHOIS
Footprinting เน้นรายละเอียดทางเทคนิคของโครงสร้างพื้นฐาน IT เช่น การสแกนเครือข่าย, Service Fingerprinting, DNS Enumeration
OSINT เก็บข้อมูลจากแหล่งสาธารณะ (Publicly Available Sources) โดยใช้เทคนิคการค้นหาขั้นสูง
Enumeration การโต้ตอบโดยตรงกับระบบเป้าหมายเพื่อดึงข้อมูลเชิงลึก เช่น บัญชีผู้ใช้ กลุ่ม Network Shares และซอฟต์แวร์

8. ประเภทของ Reconnaissance

  • Passive Reconnaissance (OSINT): การสืบค้นข้อมูลโดยไม่ส่งแพ็กเก็ตทราฟฟิกตรงไปยังเครื่องเป้าหมายเพื่อเลี่ยงการตรวจจับ เช่น WHOIS, DNS Queries สาธารณะ, Google Dorking, OSINT Framework และการวิเคราะห์เนื้อหาเว็บไซต์
  • Active Reconnaissance: การติดต่อสื่อสารโดยตรงกับเครื่องเป้าหมาย เช่น Host Enumeration, Network Enumeration, User/Group Enumeration, Network Share Enumeration, Web Page Enumeration, Service Enumeration และ Packet Crafting

9. เครื่องมือสำหรับ Passive Reconnaissance / OSINT

เครื่องมือ การใช้งาน
whois ค้นหาข้อมูลเจ้าของโดเมน/IP Block เช่น Registrant, Admin/Tech Contact, Registrar, วันที่จดทะเบียน/หมดอายุ, Name Servers ตัวอย่าง: whois target.com
nslookup / host / dig สอบถามระเบียน DNS เช่น NS, MX, A และลองทำ Zone Transfer (AXFR) หาก DNS ตั้งค่าผิดพลาดจะเปิดเผย subdomain ทั้งหมด ตัวอย่าง: nslookup -type=ns target.com, dig @<IP> domain.com AXFR
Google Dorking ใช้ตัวดำเนินการค้นหา เช่น site:target.com filetype:pdf, site:target.com inurl:admin, allintitle:index of, inurl:login และดู Google Hacking Database (GHDB) บน Exploit-DB
Shodan เสิร์ชเอนจินสำหรับอุปกรณ์ที่เชื่อมต่ออินเทอร์เน็ต (search engine for hackers) ใช้ตัวกรอง เช่น port:21, os:Linux, country:TH, product:Apache, net:192.0.2.0/24
theHarvester รวบรวม Emails, Hosts, Subdomains และ URLs จากแหล่งสาธารณะ (มีทั้ง Passive และ Active Modules) ตัวอย่าง: theHarvester -b yahoo -d target.com
recon-ng OSINT Framework เขียนด้วย Python สำหรับ Footprinting อัตโนมัติ เช่น marketplace install hackertarget, modules load hackertarget, options set source target.com, run, show hosts
OSINT Framework https://osintframework.com/ — โครงสร้างต้นไม้รวมเครื่องมือและแหล่งข้อมูล OSINT ตามหมวดหมู่ (Username, Email, Social Media, Dark Web ฯลฯ)

10. Linux Essentials สำหรับงาน Pentest

คำสั่งพื้นฐาน (Navigation & File)

  • pwd แสดงตำแหน่งไดเรกทอรีปัจจุบัน   ls -la แสดงรายการไฟล์รวมไฟล์ซ่อน
  • cd [directory] เปลี่ยนไดเรกทอรี   mkdir สร้างไดเรกทอรี   rm ลบไฟล์   rmdir ลบไดเรกทอรีว่าง
  • cp [source] [destination] คัดลอก   mv [source] [destination] ย้าย/เปลี่ยนชื่อ
  • cat [file] แสดงเนื้อหาไฟล์   nano/vim เปิดแก้ไขไฟล์   touch [file] สร้างไฟล์ว่าง
  • grep keyword filename ค้นหาคำในไฟล์   man [cmd] เปิดคู่มือคำสั่ง

สิทธิ์การเข้าถึงไฟล์ (File Permission)

  • chmod [permissions] [file] เปลี่ยนสิทธิ์ โดยค่า R=4, W=2, X=1 เช่น chmod 755 คือ rwxr-xr-x
  • chown [user:group] [file] เปลี่ยนเจ้าของไฟล์   chgrp [group] [file] เปลี่ยนกลุ่ม

กระบวนการและข้อมูลระบบ (Process & System Info)

  • ps แสดงกระบวนการปัจจุบัน   kill [PID] / pkill [name] จบกระบวนการ
  • uname -a ข้อมูลระบบ   df -h พื้นที่ดิสก์   free -h หน่วยความจำ   uptime เวลาทำงาน
  • top/htop ดูกระบวนการแบบเรียลไทม์

เครือข่าย (Networking)

  • ip a / ifconfig แสดง Network Interface และ IP
  • ping [host] ทดสอบการเชื่อมต่อ   ip r / route -n ตารางเส้นทาง
  • netstat / ss -tuln แสดงพอร์ตที่เปิดและสถานะการเชื่อมต่อ
    • netstat -l พอร์ตที่ Listening   netstat -a พอร์ตทั้งหมด   netstat -t TCP   netstat -u UDP
  • cat /etc/resolv.conf ตรวจสอบ DNS Settings

บัญชีผู้ใช้, แพ็กเกจ และอื่นๆ

  • whoami ผู้ใช้ปัจจุบัน   passwd เปลี่ยนรหัสผ่าน   useradd [username] เพิ่มผู้ใช้
  • sudo apt update / sudo apt upgrade / sudo apt install [pkg] / sudo apt remove [pkg]
  • wget [url] ดาวน์โหลดไฟล์   echo [text] แสดงข้อความ   history ประวัติคำสั่ง   mount ระบบไฟล์ที่เมานต์

ตัวดำเนินการต่อคำสั่ง (Command Chaining Operators)

  • & รันโปรแกรมเบื้องหลัง (Background)
  • && รันคำสั่งถัดไปเฉพาะเมื่อคำสั่งก่อนหน้าสำเร็จ (Logical AND)
  • | Pipe — ส่งผลลัพธ์ของคำสั่งก่อนหน้าเป็น input ให้คำสั่งถัดไป
  • > เขียนทับไฟล์   >> ต่อท้ายไฟล์

โครงสร้างไฟล์ Linux ที่สำคัญ

Directory ความสำคัญต่อการทำ Pentest
/bin โปรแกรมที่ execute ได้ — เป็นที่นิยมเก็บสคริปต์เพื่อคงการเข้าถึง (Persistence)
/etc ไฟล์ตั้งค่าระบบ — แหล่งหาข้อมูล Credentials เช่น /etc/shadow, /etc/passwd
/home ไดเรกทอรีบ้านของผู้ใช้
/opt ซอฟต์แวร์ของบริษัทบุคคลที่สาม (Third-party software)
/tmp พื้นที่ชั่วคราว (ถูกล้างเมื่อรีบูต) — เหมาะสำหรับวาง Enumeration Scripts
/var ไฟล์ Log — ที่เก็บหลักฐานการโจมตี

11. รายละเอียดขั้นตอนปฏิบัติการ Lab (Step-by-Step Practical Guide)

ตอนที่ 1: การสำรวจและทดสอบการเชื่อมต่อเครือข่าย

  • ตรวจสอบ Interface และ IP Address: รันคำสั่ง ip a เพื่อตรวจสอบว่า Kali ได้รับ IP ของวงทดสอบถูกต้องหรือไม่
  • ทดสอบการเชื่อมต่อ: รันคำสั่ง ping -c 4 <Target_IP> เพื่อยืนยันว่าสามารถสื่อสารกับเป้าหมายได้โดยไม่มี Packet Loss

ตอนที่ 2: การสืบค้นข้อมูลเป้าหมายด้วยเทคนิค Passive Recon (OSINT)

  • ตรวจสอบข้อมูลการจดทะเบียนโดเมน: รันคำสั่ง whois target.com เพื่อค้นหารายละเอียดผู้ถือครองโดเมนและ Name Servers
  • สืบค้นระเบียนข้อมูล DNS: ใช้คำสั่ง nslookup -type=ns target.com, nslookup -type=mx target.com หรือ host -a target.com เพื่อแจกแจง Mail Server และ Subdomains
  • ค้นหาข้อมูลลับและโครงสร้างเว็บ (Google Dorking): ทำการค้นหาผ่านเว็บเบราว์เซอร์ด้วยคำสั่งเฉพาะ เช่น site:target.com filetype:pdf, site:target.com inurl:admin, site:target.com ext:sql | ext:log

ตอนที่ 3: การจัดการระบบไฟล์และการสร้าง Wordlist สำหรับบันทึกผล

  • สร้างโฟลเดอร์สำหรับแล็บ: ใช้คำสั่ง mkdir -p ~/Pentest_Labs/Lab2 และย้ายตำแหน่งด้วย cd ~/Pentest_Labs/Lab2
  • สร้างไฟล์พจนานุกรมชื่อบัญชี: ใช้ Text Editor ผ่านคำสั่ง nano user_list.txt เพื่อระบุรายชื่อผู้ใช้ที่น่าสงสัย (เช่น admin, root, msfadmin) บรรทัดละ 1 รายการ
  • ตรวจสอบความถูกต้อง: ใช้คำสั่ง ls -la และ cat user_list.txt เพื่อตรวจสอบการสร้างไฟล์และสิทธิ์การเข้าถึง
แบบฝึกหัด Linux เพิ่มเติม: ฝึก Navigation (pwd, ls, cd, mkdir, rm), File Permissions (chmod, chown), Process Management (ps, kill, top), Network (ip a, ip r, ping, traceroute, ss -tuln) และ Package Management (apt update / upgrade / install / remove) ตามแบบฝึกหัดในสไลด์เพื่อปูพื้นฐานก่อนการทดสอบเจาะระบบ

12. สรุปรายการหลักฐานที่ต้องบันทึก (Assignment Checklist)

  • ภาพแสดงผลลัพธ์คำสั่ง ip a และการ ping เครื่องเป้าหมายสำเร็จ
  • ภาพผลการตรวจสอบข้อมูล Domain และ DNS Records (WHOIS / Nslookup / Host)
  • ภาพตัวอย่างการใช้ Google Dorking บน Web Browser
  • ภาพ Terminal แสดงโครงสร้างโฟลเดอร์และเนื้อหาไฟล์ Wordlist ที่สร้างขึ้นบน Kali Linux
