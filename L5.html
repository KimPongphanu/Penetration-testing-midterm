สรุปเนื้อหาและปฏิบัติการ Lecture 5: Vulnerability Assessment

วิชา Penetration Testing and Protection (0406136051)

1. สรุปเนื้อหาสำคัญ (Theoretical Overview)

  • Vulnerability Assessment (VA): กระบวนการตรวจหา จำแนก และจัดลำดับความสำคัญของช่องโหว่บนระบบ เครือข่าย และซอฟต์แวร์ โดยเน้นการตรวจสอบเปรียบเทียบกับฐานข้อมูลช่องโหว่ที่ทราบแล้ว (Known Vulnerabilities)
  • ความแตกต่างกับ Pentest: VA เน้นการค้นหาและประเมินระดับความเสี่ยงของจุดอ่อนทั้งหมด (Assessment) ในขณะที่ Penetration Testing มุ่งเน้นการเจาะผ่านระบบป้องกันเพื่อพิสูจน์ผลกระทบจริง
  • ความหมายของ Vulnerability: จุดอ่อนที่อาจนำไปสู่การประนีประนอมความปลอดภัยของข้อมูล แบ่งเป็น 3 ประเภท
    • Technological: จุดบกพร่องในเทคโนโลยีที่นำมาใช้ เช่น ความผิดพลาดในแอปพลิเคชัน X ที่ทำให้ควบคุมระบบ Y ได้
    • Configuration: เกิดจากการตั้งค่าระบบที่ผิดพลาด เช่น ผู้ดูแลเปิดพอร์ต RDP บน Firewall ไว้โดยไม่จำเป็น
    • Policy: การขาดนโยบายความปลอดภัยหรือไม่ปฏิบัติตาม เช่น ประตู Data Center ไม่ได้ล็อก
  • งานของ Vulnerability Assessment & Management: สแกนระบบเป้าหมาย, สร้างรายงานผลการสแกน, วิเคราะห์รายงาน, จัดลำดับความเสี่ยงของแต่ละช่องโหว่, ตัด False Positives ออก และรวบรวมรายงานช่องโหว่จริง
  • ระดับความเสี่ยง (Risk Levels):
    • High Risk: มีช่องโหว่ร้ายแรงที่โจมตีได้ง่าย นำไปสู่การควบคุมระบบทั้งหมด — ต้องแก้ไขทันที
    • Medium Risk: ช่องโหว่รุนแรงแต่ต้องใช้ความซับซ้อนในการโจมตี — ควรแก้ไขในระยะสั้น
    • Low Risk: ช่องโหว่ระดับปานกลางที่ให้ข้อมูลแก่ผู้โจมตี — แก้ไขได้แต่ไม่เร่งด่วน
  • ข้อดี/ข้อเสียของ Vulnerability Scanner:
    • ข้อดี: ทำให้งานอัตโนมัติ เช่น Reconnaissance, Port Scanning, Service & Version Detection
    • ข้อเสีย: ส่งทราฟฟิกจำนวนมากตรวจจับได้ง่าย (Loud), เกิด False Positives และ False Negatives

2. ระบบมาตรฐานและการให้คะแนนช่องโหว่

ระบบ รายละเอียด
CVE (Common Vulnerabilities and Exposures) ฐานข้อมูลช่องโหว่ที่รู้จัก จัดการโดย MITRE Corporation แต่ละช่องโหว่มีรหัสประจำตัวเฉพาะ เช่น CVE-2011-2523, CVE-2014-3566
NVD (National Vulnerability Database) ฐานข้อมูลช่องโหว่ของรัฐบาลสหรัฐฯ (nvd.nist.gov) ที่วิเคราะห์ข้อมูลต่อยอดจาก CVE และระบุระดับความรุนแรงด้วยคะแนน CVSS
CVSS (Common Vulnerability Scoring System) เฟรมเวิร์กประเมินความรุนแรงของช่องโหว่ จัดการโดย FIRST มีเวอร์ชัน 4.0 แบ่งเป็น 4 กลุ่มเมตริก: Base, Threat, Environmental, Supplemental
CWE (Common Weakness Enumeration) รายการจุดอ่อนที่พัฒนาร่วมกันโดยชุมชน (Community-developed) ซึ่งเป็น Root Cause ของ CVE Records
KEV (Known Exploited Vulnerabilities) ช่องโหว่ที่ถูกระบุว่ามีการโจมตีจริง (Actively Exploited) — องค์กรควรจัดการเร่งด่วน

ระดับคะแนน CVSS (เวอร์ชัน 4.0)

ระดับ ช่วงคะแนน
None 0.0
Low 0.1 – 3.9
Medium 4.0 – 6.9
High 7.0 – 8.9
Critical 9.0 – 10.0

กลุ่มเมตริก CVSS 4.0

  • Base Metrics: ลักษณะภายในของช่องโหว่ที่คงที่ตามเวลาและสภาพแวดล้อม
    • Attack Vector (AV): Network (N) / Adjacent (A) / Local (L) / Physical (P)
    • Attack Complexity (AC): Low (L) / High (H)
    • Attack Requirements (AT): None (N) / Present (P)
    • Privileges Required (PR), User Interaction (UI), และเมตริกผลกระทบ (Confidentiality/Integrity/Availability)
  • Threat Metrics: สะท้อนระดับภัยคุกคาม (เช่น มี Exploit สาธารณะหรือไม่)
  • Environmental Metrics: ปรับคะแนนตามสภาพแวดล้อมขององค์กร เช่น Security Requirements (CR/IR/AR), Modified Impact Metrics
  • Supplemental Metrics: ไม่กระทบคะแนนสุดท้ายแต่ให้บริบทเพิ่ม เช่น Safety (S), Automatable (AU), Recovery (R), Value Density (V), Vulnerability Response Effort (RE), Provider Urgency (U)
Nomenclature CVSS 4.0: CVSS-B (Base), CVSS-BT (Base + Threat), CVSS-BE (Base + Environmental), CVSS-BTE (Base + Threat + Environmental) — ใช้เครื่องคิดเลขออนไลน์ได้ที่ https://nvd.nist.gov/vuln-metrics/cvss/v4-calculator

ขั้นตอนของ Vulnerability Assessment

  • ตรวจสอบว่าเป้าหมายยังทำงานอยู่ด้วย ICMP (Ping)
  • สแกนพอร์ตที่เปิดอยู่ด้วยวิธี Stealth และทดสอบพอร์ต
  • ระบุช่องโหว่ที่อาจเกิดขึ้นและสร้างรายงานด้วย Network Vulnerability Scanner
  • จำแนกช่องโหว่และวางแผนการตอบสนอง
  • จำแนกทรัพย์สินหลักและทำ Risk Management
  • จัดทำเอกสาร/รายงานติดตามผล (Follow-up Documentation)
  • เริ่มต้นความพยายามด้านความปลอดภัยอย่างต่อเนื่อง (Ongoing Security Effort)

3. เครื่องมือวิเคราะห์ช่องโหว่ (Vulnerability Scanners)

เครื่องมือ รายละเอียด
Nmap Scripting Engine (NSE) สคริปต์เขียนด้วยภาษา Lua อยู่ที่ /usr/share/nmap/scripts หมวด vuln ใช้ตรวจสอบช่องโหว่เฉพาะบริการอย่างรวดเร็ว เช่น ftp-vsftpd-backdoor, ssl-poodle, ftp-anon, ssh-auth-methods
Tenable Nessus สแกนเนอร์ระดับโฮสต์และเครือข่ายที่มีฐานข้อมูลช่องโหว่ขนาดใหญ่ รองรับ Credentialed Scans, Compliance Auditing และรายงานผลละเอียดพร้อมแนวทางแก้ไข (Remediation) — เวอร์ชันฟรีคือ Nessus Essentials (สแกนได้สูงสุด 16 IP)
OWASP ZAP (Zed Attack Proxy) สแกนเนอร์โอเพนซอร์สฟรีจาก OWASP สำหรับตรวจสอบช่องโหว่ระดับเว็บแอปพลิเคชันโดยเฉพาะ รองรับทั้ง Automated Scan และ Manual Testing

องค์ประกอบของรายงาน Vulnerability Assessment

  • Executive Summary: สรุปขอบเขต ระเบียบวิธี ผลการค้นพบหลัก ระดับความรุนแรง และข้อเสนอแนะสำคัญ
  • Introduction: วัตถุประสงค์ ขอบเขต (ระบบ/เครือข่าย/แอปพลิเคชัน) ระเบียบวิธี และกลุ่มผู้อ่าน
  • Findings: รายละเอียดช่องโหว่ที่พบ (แบ่งตาม Critical/High/Medium/Low), Vulnerability ID, คำอธิบาย, ตำแหน่ง, ผลกระทบ, หลักฐาน/PoC และการประเมินความเสี่ยง
  • Risk Assessment: ภาพรวมสถานะความปลอดภัยขององค์กร, ลำดับความสำคัญ และทรัพย์สินวิกฤต
  • Recommendations: แนวทางแก้ไขที่ชัดเจน ปฏิบัติได้จริง, แผน Remediation ที่จัดลำดับตามความเสี่ยง และการวิเคราะห์ Cost-Benefit
  • Appendix: ข้อมูลทางเทคนิคโดยละเอียด (ผลสแกน, Logs, ภาพหน้าจอ, แผนภาพเครือข่าย)

4. รายละเอียดขั้นตอนปฏิบัติการ Lab (Step-by-Step Practical Guide)

ตอนที่ 1: การสแกนช่องโหว่ด้วย Nmap NSE Scripts

  • อัปเดตฐานข้อมูล NSE Script: รันคำสั่ง sudo nmap --script-updatedb
  • สแกนช่องโหว่ทั้งระบบด้วยสคริปต์หมวด vuln: รันคำสั่ง nmap --script vuln <Target_IP> เพื่อตรวจหาช่องโหว่ เช่น ftp-vsftpd-backdoor (CVE-2011-2523) หรือ ssl-poodle (CVE-2014-3566)
  • ตรวจสอบการล็อกอินนิรนามบน FTP: รันคำสั่ง nmap --script ftp-anon <Target_IP>

ตอนที่ 2: การสแกนระบบและเครือข่ายด้วย Tenable Nessus

  • เริ่มต้นเซอร์วิส Nessus: รันคำสั่ง sudo systemctl start nessusd
  • เข้าใช้งานและสร้างงานสแกนใหม่: เข้าเบราว์เซอร์ไปที่ https://localhost:8834 ไปที่ New Scan → เลือกเทมเพลต Basic Network Scan → ใส่ Target IP แล้วกด Save → Launch
  • วิเคราะห์ผลการสแกน: เปิดแท็บ Vulnerabilities กรองดูระดับ CRITICAL และ HIGH พร้อมอ่านรายละเอียดคำอธิบาย (Description) และแนวทางแก้ไข (Solution)

ตอนที่ 3: การสแกนเว็บแอปพลิเคชันด้วย OWASP ZAP

  • ติดตั้ง OWASP ZAP: ติดตั้งผ่าน Kali Package Manager: sudo apt update แล้ว sudo apt install zaproxy
  • เปิดใช้งาน OWASP ZAP: รันคำสั่ง zaproxy ใน Terminal หรือเปิดผ่านไอคอนโปรแกรม แล้วเลือกโหมด Standard UI พร้อม Persist Session (ไฟล์ .zap)
  • ทำการสแกนเป้าหมาย (Active Scan): ใส่ URL: http://<Target_IP>/ ในหน้าต่าง Quick Start / Automated Scan แล้วกดสั่งสแกน หรือตั้งค่า Proxy เบราว์เซอร์ชี้ไปที่ 127.0.0.1:8080 แล้วคลิกขวาที่ชื่อโฮสต์เพื่อเลือก Attack → Active Scan
  • ติดตั้ง ZAP Root CA Certificate: เข้าเว็บ http://zap/ จากเบราว์เซอร์ที่ตั้ง Proxy แล้วดาวน์โหลดและ Import Certificate เพื่อให้สามารถสแกน HTTPS ได้
  • ตรวจสอบรายงานผล (Alerts): ดูรายการแจ้งเตือน เช่น Remote Code Execution (CVE-2012-1823), Path Traversal, Missing Security Headers และสามารถส่งออกรายงานเป็นไฟล์ HTML ผ่านเมนู Report

5. สรุปรายการภาระงานที่ต้องส่ง (Assignment Checklist หน้า 84)

  • รายงานผลจาก Nessus: สรุปรายการช่องโหว่ระดับ CRITICAL ทั้งหมดที่พบบนเครื่อง Metasploitable2 โดยระบุว่าพบที่ Port ใด และรัน Service อะไร
  • การเปรียบเทียบผลลัพธ์: เปรียบเทียบผลระหว่าง Nessus (ครอบคลุมระดับ Host / OS / Network Services ทั่วทั้งระบบ) กับ OWASP ZAP (เน้นเฉพาะจุดอ่อนบน Web Application Layer ที่รันบนพอร์ต 80)
