PHASE 1 · Foundation & MethodologyL1 — Setup Field

🎯 Objective: เข้าใจขอบเขต จริยธรรม และแยก VA กับ PT ให้ได้ + เตรียมสภาพแวดล้อมแล็บ (Kali & Metasploitable2)

Pentest = Ethical Hacking: จำลองโจมตีอย่างถูกกฎหมาย หาจุดอ่อนก่อนผู้ไม่หวังดี — ประเมิน controls 3 ด้าน: Technological / Procedural / Operational · ต้องมี ROE อนุมัติก่อนเสมอ

Pentester: ใช้ TTP (tools/techniques/processes) เดียวกับ attacker เพื่อพิสูจน์ business impact ของจุดอ่อน แล้วแนะนำ mitigation

คู่เปรียบเทียบ (ออกสอบบ่อย)ต่างกันยังไง
VA Vulnerability Assessmentเช็กทั้งบ้านเทียบรายการ known vulnerabilities — กว้าง · ไม่เปิดประตู · ได้ list+ความเสี่ยง
PT Penetration Testingสวมบทโจรงัดบ้านจริง — ลึก · พิสูจน์เข้าได้+ผลกระทบ · มี scope/ROE
Red TeamingPT adversarial — ซ่อนไม่ให้ Blue Team รู้ วัดการตอบโต้
Vuln Scan ⊂ VA ⊂ PT ⊂ Red Teamรัน scanner ⊂ +validate ⊂ +exploit ⊂ +ศึกจำลองมีทีมรับ
  • Black box: ให้แต่ IP ranges = โจรนอก · White box: ให้ source code/configs · Gray box: ให้บัญชีพนักงานธรรมดา
  • By target: Network / Physical / Web application / Wireless

  • Msf: v1(2010 เก่า) / v2(2012 เป้าหลัก) / v3(+Windows)

➜ Hand-off → PHASE 2: Lab พร้อม+กติกาชัดแล้ว → step แรกของการโจมตีคือ "หาข้อมูลเป้าหมาย" โดยยังไม่ให้เขารู้ตัว

PHASE 2 · Passive Recon & LinuxL2 — สืบข่าวโดยเขาไม่รู้ตัว

🎯 Objective: เก็บข้อมูลจากแหล่งสาธารณะ (OSINT / Dorking / WHOIS) โดยไม่แตะระบบตรงๆ เพื่อไม่ให้เป้าหมายรู้ตัว + ปูพื้น Linux commands

ศัพท์ (ซ้อนเป็นชั้น)แปลง่ายๆ
Information Gatheringร่มใบใหญ่ครอบการเก็บข่าวทุกแบบ
Reconnaissanceส่องภาพรวม: web/social/IP range/domain/email
Footprintingซูม technical: net scan, fingerprint, DNS subdomain
OSINTข้อมูล public + advanced search
Enumerationเคาะถามตรง: users/shares/apps/configs
  • Passive = ไม่แตะ target (อ่านข้อมูลที่คนอื่นเก็บไว้) → ไม่มี log · ทำก่อนเสมอ
  • Active = ส่ง packet หา target → มี footprint · ข้อมูลลึก/ทันสมัยกว่า
  • Why: วาง scope · หา attack surface · ยิงตรงจุดประหยัดเวลา · ลดการถูกตรวจจับ
Tool → ตอบคำถามอะไร
Toolตอบว่า…
WHOISเจ้าของ domain/IP · dates · NS ค่ายไหน
DNS / Zone transfermail server · subdomain ซ่อน (AXFR สำเร็จ=DNS config พลาด ได้แผนที่เต็ม)
Google Dorkingไฟล์/admin page/index หลุดผ่าน operators

Linux (มุม security)

  • rwx: R=4 W=2 X=1 → 755=rwxr-xr-x · root=ทำได้ทุกอย่าง
  • Chaining: && conditional · | pipe · > overwrite · >> append · & background

➜ Hand-off → PHASE 3: ได้ IP range/domain กว้างๆ แล้ว → เริ่มส่ง packets เข้าไปสำรวจโดยตรง (Active)

PHASE 3 · Active ScanningL3 — เคาะประตูทีละบาน

🎯 Objective: ใช้ Nmap หา live hosts + open ports + service/version + OS — รู้ว่า "ประตูไหนเปิด ใครยืนหลังประตู"

Scan goals: live systems · open ports · service+version · OS fingerprint · target IP

Port stateแปลว่า
Openservice listen จริง (SYN→SYN/ACK)
Closedไม่มี service (SYN→RST)
Filteredfirewall drop — มองไม่เห็นข้างหลัง
ตระกูลเทคนิค (หลักคิด)
FamilyIdea / เด่น
Full connecthandshake ครบ — accurate, no-root, log ชัด
SYN half-openครึ่งจังหวะแล้ว RST — stealth standard, need root
FIN/XMAS/NULLธงแปลก อาศัย RFC (silent=open) — หวังหลบ log
ACKสอบ firewall stateful ไม่ใช่หา port เปิด
UDPsilent=open/filtered กำกวม — ช้า แต่ DNS/SNMP ต้องใช้
FTP bounceยืม FTP server เป็นนายพล — ซ่อนตัว

Port↔Service: 21 FTP · 22 SSH · 23 Telnet · 25 SMTP · 53 DNS · 80 HTTP · 110 POP3 · 143 IMAP · 161 SNMP · 443 HTTPS · 139 NetBIOS · 445 SMB · 3389 RDP

  • Version detection: ถามว่า service เวอร์ชันไหน → version = กุญแจหา CVE ใน PHASE 5–6
  • OS fingerprint: อ่านนิสัย TCP/IP stack
  • Aggressive: version+OS+scripts+traceroute ชุดเดียว (ดังสุด)
  • Outputs: normal/greppable/XML/all — เก็บหลักฐาน+ประมวลต่อ · Host discovery: ping sweep/masscan หา alive ก่อน

➜ Hand-off → PHASE 4: รู้ ports เปิดแล้ว → เจาะลึกรายละเอียด "ใครใช้ port นั้น ตั้งค่าอะไรไว้"

PHASE 4 · Deep EnumerationL4 — เปิดตู้เซฟดูของข้างใน

🎯 Objective: ดึงข้อมูลเชิงลึก — Users / Shares / Configs / Hidden paths — จาก SMB, RPC, Web เพื่อ map attack surface ภายใน

Enumeration = คุยกับ open service โดยตรง — user list→brute-force · share→วางไฟล์/ข้อมูลหลุด · config พลาด→ช่องตรง · เป็นสะพาน "port เปิด" → "ทางเข้า"

Protocolบอกอะไรได้
SMB (139/445)แชร์ไฟล์ Windows/Samba — users/groups/shares/processes
RPC (111)portmapper ทำเนียบ services — nfs/mountd…
NFS (2049)export โฟลเดอร์ให้ใคร ("/" = ทั้งเครื่อง!)
NetBIOS (137–139)ชื่อเครื่อง legacy
Web (80/443)hidden paths/admin panel/phpinfo

Tools หน้าที่: smbclient=เดินเข้า share · SMBMap=แผนที่สิทธิ์ share · enum4linux=users/groups/OS ครบชุด · NBTscan/nbstat=NetBIOS names · http-enum/Nikto=path+web vulns · default-scripts mode=fingerprint อัตโนมัติตาม port

➜ Hand-off → PHASE 5: ได้ service versions + internal structure ครบแล้ว → นำไปเทียบฐานข้อมูล หาว่ามีช่องโหว่อะไรบ้าง

PHASE 5 · Vulnerability AnalysisL5 — จัดอันดับความอันตราย

🎯 Objective: scan เทียบ known CVEs (NSE / Nessus / ZAP) + ให้คะแนน severity ด้วย CVSS → ได้ list Critical/High ก่อนเจาะจริง

VA = หา+จำแนก+จัดลำดับช่องโหว่เทียบ known DB — focus discovery & evaluation ไม่ break-in · ทดสอบ detection/response: DoS, MITM, SQLi, intrusion

ชนิด vulnตัวอย่าง
Technologicalbug ใน software (app X → control system Y)
Configurationตั้งค่าพลาด (RDP เปิดค้างบน firewall)
Policyไม่มี/ไม่ทำตามกฎ (server room ไม่ล็อก)
Riskความหมายเร่ง?
Highโจมตีง่าย เสียทั้งระบบทันที
Mediumยากขึ้น/ได้น้อยระยะสั้น
Lowinfo ให้ attacker ต่อไม่ด่วน
  • Scanner ±: (+) auto เร็ว ครอบคลุม (−) loud + false pos/neg → ต้อง verify manual
  • VA steps: ping alive → stealth port scan → scanner หา vuln+report → classify+response plan → key assets hierarchy → follow-up docs → ongoing security effort
CVSS v4.0 (FIRST) — ไม้บรรทัด severity
  • Groups: Base(ธรรมชาติ vuln) / Threat(exploit situation) / Environmental(ปรับตามองค์กร) / Supplemental(context ไม่มีผล score)
  • Base: AV(N/A/L/P) · AC(L/H) · AT(N/P) · PR · UI + Impact C/I/A ×2 systems · Names: CVSS-B/BT/BE/BTE
  • Bands: None 0.0 · Low 0.1–3.9 · Medium 4.0–6.9 · High 7.0–8.9 · Critical 9.0–10.0
  • CVE=ID โดย MITRE (2523 vsftpd backdoor · 3566 POODLE · 1823 PHP-CGI RCE) · NVD=CVE+CVSS analysis · CWE=root cause list · KEV=actively exploited รีบแก้
  • Report: Exec Summary → Introduction → Findings(ID/desc/impact/PoC/risk) → Risk Assessment → Recommendations → Appendix · Tips: ชัด มีภาพ เรียง severity actionable
  • Tools 3 สาย: NSE(vuln scripts ราย service) · Nessus(host/network ครบ+remediation) · ZAP(webapp proxy+active scan)

➜ Hand-off → PHASE 6: ได้รายชื่อ Critical/High แล้ว → พิสูจน์ PoC ด้วยการเจาะจริงว่าเข้าถึงระบบได้หรือไม่

PHASE 6 · ExploitationL6 — พิสูจน์ว่างัดได้จริง

🎯 Objective: นำ CVE ที่ตรวจพบ มาเลือก Exploit + Payload ใน Metasploit (หรือ script เฉพาะทาง) เพื่อเอา Initial Access / Root Shell — พิสูจน์ impact จริง

Exploit = bypass security flaw/control — vector ต่างกันตาม OS/service/version แต่เป้าหมายคือ unauthorized access/control/info · ไม่ใช่ "พังให้ได้" แต่คือ พิสูจน์ impact + ความลึกของ flaw เพื่อ report ที่หนักแน่น

Goals (5)แปลง่าย
Validate Vulnerabilitiesscanner ว่าใช่ — จริงป่าว
Assess Impactโจรใช้ เจ็บแค่ไหน
Gain Accessshell/บัญชี/ข้อมูล ไม่อนุญาต
Elevate Privilegesuser → root/SYSTEM
Persistenceกุญแจสำรองกลับมาใหม่ได้
4 ช่วงของ Phase
  1. Prep/Planning: คัด vulns (severity/impact/exploitability) → เตรียม/custom exploit
  2. Execute: launch → initial foothold (account/shell/web control)
  3. Post-Exploitation: privesc → system enum (sw/net/security) → data exfil พิสูจน์ breach → persistence (backdoor/accounts/config)
  4. Cleanup & Docs: ลบ artifacts + document findings → report
Metasploit = ชุดต่อเจาะ
  • Modules 7: Exploits(ลูกศร) · Payloads(ดินระเบิด: reverse/meterpreter) · Encoders(ห่อหุ้มหลบ AV/IDS) · Auxiliary(scan/fuzz/brute) · NOP(filler) · Post(privesc/เก็บ creds) · Evasion(หลบ EDR)
  • Architecture: Rex(sockets) → MSF Core(session/UI/module) → MSF Base(API msfconsole) — UIs: msfconsole / Armitage(GUI)
  • Reverse vs Bind (ออกสอบ): Bind = เราโทรเข้า (target เปิด port รอ) · Reverse = target โทรกลับหาเรา (ผ่าน NAT/FW ได้ นิยมกว่า)
  • Connection: Auto เลือกเองตาม NAT · Settings: RHOSTS/RPORT target · LHOST/LPORT รับ reverse

➜ จบ Scope L1–L6: พิสูจน์แล้วว่า "เข้าได้จริง+impact เท่าไร" → งานต่อไปคือ เขียน Report (ไม่อยู่ในขอบเขตข้อสอบ phase chain นี้)

⚡ Quick Recall ก่อนเข้าห้องสอบ10 ข้อต้องไม่ลืม

  2. VA=กว้าง known-list · PT=ลึกพิสูจน์ impact — ไม่แทนกัน
  3. Black=โจรนอก · White=แบบแปลน+code · Gray=บัญชีธรรมดา
  4. PTES 7: Pre-engage → Intel → Threat Model → Vuln Analysis → Exploit → Post → Report
  5. Passive ไม่มี log · Active เริ่มมี footprint — passive ก่อนเสมอ
  6. /etc=password · /tmp=วาง script · /bin=persistence · /var=หลักฐาน
  7. Open/Closed/Filtered · SYN=stealth · ACK=สอบ firewall · UDP=กำกวม
  8. Port: 21 FTP · 22 SSH · 25 SMTP · 80 HTTP · 443 HTTPS · 445 SMB · 3389 RDP
  9. CVSS: None 0 · Low <4 · Med <7 · High <9 · Critical ≥9 · CVE=ID · KEV=โจรใช้จริง
