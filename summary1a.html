L1 · Foundation & Methodologyรู้จักเกม+กติกา ก่อนลงสนาม

Pentest คือ: จำลองการโจมตีอย่างถูกกฎหมาย เพื่อหาจุดอ่อนก่อนผู้ไม่หวังดี — ต่างจากแฮกเกอร์ตรงที่มีขอบเขต + ส่งรายงานช่วยให้องค์กรแข็งแรงขึ้น (ประเมิน controls 3 ด้าน: เทคโนโลยี / ขั้นตอน / การปฏิบัติ)

Pentester: ใช้วิธี+เครื่องมือแบบ attacker เพื่อพิสูจน์ว่าจุดอ่อนสร้างความเสียหายจริงแค่ไหน แล้วแนะนำวิธีแก้

  • Black box: ให้แต่ที่อยู่ (IP ranges) = โจรข้างนอก · White box: ให้แบบแปลน+source code/configs · Gray box: ให้บัญชีพนักงานธรรมดา
  • ตามเป้าหมาย: Network / Physical (ล็อก กล้อง sensor) / Web application / Wireless

L2 · Passive Recon & Linux"สืบข่าวโดย target ไม่รู้ตัว"
ศัพท์ (ซ้อนกันเป็นชั้น)แปลง่ายๆ
Information Gatheringร่มใบใหญ่ ครอบการเก็บข่าวทุกแบบ
Reconnaissanceส่องภาพรวมจากข้างนอก: เว็บ/โซเชียล/IP range/โดเมน/อีเมล
Footprintingซูมเข้ารายละเอียด technical: network scan, service fingerprint, DNS subdomain
OSINTเก็บจากแหล่งสาธารณะ+search ขั้นสูง
Enumerationเคาะประตูถามตรงๆ — users/shares/apps/configs
  • Passive = ไม่แตะ target (อ่านข้อมูลที่คนอื่นเก็บไว้แล้ว) → ไม่มี log · ทำก่อนเสมอเพื่อความเนียน
  • Active = ส่งอะไรบางอย่างหา target → เริ่มมี footprint · เก็บได้ลึก/ทันสมัยกว่า
  • ทำไม recon สำคัญ: กำหนด scope · หา attack surface · เลือกยิงตรงจุด ประหยัดเวลา · ลดโอกาสโดนจับได้
เครื่องมือ passive แต่ละตัวตอบคำถามอะไร

Linux ที่ต้องรู้ (มุม security)
  • /etc = config + รหัสผ่าน (passwd, shadow) → ที่หอกข้าวของ attacker · /var = logs (หลักฐาน) · /tmp = ขยะชั่วคราว (จุดวาง script) · /bin = โปรแกรม (จุดฝัง persistence) · /home /opt /usr
  • Permission rwx: Read=4 Write=2 eXecute=1 → 755 = เจ้าของทำได้หมด คนอื่นอ่าน+รัน · root = เทพ ทำได้ทุกอย่าง
  • เชื่อมคำสั่ง: && ทำต่อเมื่อสำเร็จ · | ส่งผลต่อ · > เขียนทับ · >> ต่อท้าย · & พื้นหลัง
L3 · Scanning Concepts"เคาะประตูทีละบานอย่างมีชั้นเชิง"

เป้าหมายของการสแกน: ใครยังมีชีวิต (hosts) · ประตูไหนเปิด (ports) · ใครยืนอยู่หลังประตู (services+version) · บ้านสไตล์ไหน (OS)

สถานะพอร์ตแปลวว่า
Openมี service นั่งรอรับ connection จริง
Closedเครื่องอยู่ แต่ประตูนี้ไม่มีใครใช้ (ตอบ RST)
Filteredfirewall ดักไว้ — ไม่รู้จริงว่าข้างหลังมีอะไร
ตระกูลเทคนิคสแกน (เข้าใจหลักคิด ไม่ต้องจำ flag)
ตระกูลหลักคิด / จุดเด่น
Full connect (TCP Connect)จับมือครบ 3 จังหวะ — แม่นยำ ไม่ต้องสิทธิ์พิเศษ แต่ถูกจด log ชัด
SYN half-openจับมือครึ่งจังหวะแล้ววางสาย — stealth มาตรฐาน, ต้องสิทธิ์ root
FIN / XMAS / NULLส่งธงแปลกๆ อาศัยกฎ RFC (เงียบ=open) — หวังหลบ log ของ firewall บางตัว
ACK scanไม่ได้หา port เปิด — ใช้สอบ firewall ว่า stateful หรือเปล่า
UDP scanเงียบ=เปิดหรือถูกกรอง (กำกวม) — ช้า, จำเป็นกับ DNS/SNMP/DHCP
FTP bounceยืม FTP server คนอื่นเป็นนายพล — ซ่อนตัวเรา
Port ↔ Service (ท่องให้ขึ้นใจ)

21 FTP · 22 SSH · 23 Telnet · 25 SMTP · 53 DNS · 80 HTTP · 110 POP3 · 143 IMAP · 161 SNMP · 443 HTTPS · 139 NetBIOS · 445 SMB/CIFS · 3389 RDP

ต่อยอดหลังสแกน
  • Version detection: ถามว่า service นี้เวอร์ชันอะไร — เวอร์ชัน = กุญแจไปหา CVE ใน L5–L6
  • OS fingerprinting: อ่านนิสัย TCP/IP stack → ระบบอะไร เวอร์ชันไหน
  • Aggressive mode: version+OS+default scripts+traceroute ในที่เดียว (เสียงดังสุด)
  • Output formats: normal/greppable/XML/all — เก็บเป็นหลักฐาน+นำไปประมวลต่อ
  • Host discovery: ping sweep หา "ใครยังอยู่" ก่อนสแกนลึก — masscan สำหรับวงใหญ่
L4 · Enumeration Concepts"เปิดตู้เซฟดูของข้างใน"

Enumeration = คุยกับ service ที่เปิดอยู่โดยตรง เพื่อดึงข้อมูลมีค่า: ชื่อผู้ใช้ / กลุ่ม / share / โฟลเดอร์ซ่อน / config — เป็นสะพานจาก "รู้ว่าประตูไหนเปิด" ไปสู่ "รู้ว่าจะเข้ายังไง"

  • ทำไมสำคัญ: user list → แหล่ง brute-force · share → จุดวางไฟล์/ข้อมูลหลุด · config พลาด → ช่องเข้าตรงๆ
  • Active vs Passive scan: active ครบแต่เสียงดัง · passive เนียนแต่เห็นน้อย — เลือกตามสถานการณ์+ROE
Protocolบอกอะไรเราได้
SMB (139/445)แชร์ไฟล์ Windows/Samba — users, groups, shares, process (ต้องมี creds บางอย่าง)
RPC (111)portmapper ทำเนียบบริการ — nfs/mountd ฯลฯ
NFS (2049)export โฟลเดอร์อะไรให้ใคร (ถ้า export "/" = ทั้งเครื่อง)
NetBIOS (137–139)ชื่อเครื่อง/legacy info
Web (80/443)โฟลเดอร์ซ่อน admin panel phpinfo — ประตูข้างหลังบ้าน

Tools และหน้าที่ (ไม่ต้องจำ syntax): smbclient=เดินเข้า share · SMBMap=ดูสิทธิ์ share เป็นแผนที่ · enum4linux=ดึง users/groups/OS แบบครบชุด · NBTscan/nbstat=ชื่อ NetBIOS · http-enum/Nikto=สำรวจ path+ช่องโหว่เว็บ · -sC=ชุด script อัตโนมัติตาม port

L5 · Vulnerability Assessment"จัดอันดับความอันตรายของประตูที่พบ"

VA = หา+จำแนก+จัดลำดับช่องโหว่โดยเทียบฐานข้อมูลที่รู้จัก (known vulnerabilities) — เน้น "ค้นพบ+ประเมิน" ไม่ใช่เจาะจริง · ทดสอบว่าระบบตรวจจับ/ตอบโต้ DoS, MITM, SQLi ได้ไหม

ชนิดช่องโหว่ตัวอย่างเข้าใจง่าย
Technologicalของมี bug เอง (app X พัง → ควบคุม system Y)
Configurationคนตั้งค่าพลาด (เปิด RDP ทิ้งไว้บน firewall)
Policyไม่มีกฎ/ไม่ทำตามกฎ (ประตู server room ไม่ล็อก)
Riskความหมายเร่งแค่ไหน
Highโจมตีง่าย → เสียเมืองทั้งเมืองแก้ทันที
Mediumยากหน่อย/ได้น้อยระยะสั้น
Lowให้ข้อมูลผู้โจมตีต่อค่อยว่ากัน
  • Scanner +/−: (+) อัตโนมัติ เร็ว ครอบคลุม (−) เสียงดังโดนจับได้ + false positive/negative → ต้องตรวจซ้ำด้วยมือ
  • VA steps (7): ping เช็ก alive → stealth scan ports → scanner หา vuln+report → จำแนก+วางแผนตอบ → จัด asset สำคัญ → ทำ report ตามหลัง → วางระบบรักษาภาพรวมต่อเนื่อง
CVSS v4.0 — ไม้บรรทัดวัดความรุนแรง (FIRST)
  • 4 กลุ่ม: Base(ธรรมชาติช่องโหว่) / Threat(สถานการณ์ exploit) / Environmental(ปรับตามบ้านเรา) / Supplemental(context เสริม ไม่มีผลคะแนน)
  • Base สำคัญ: AV(โจมตีจากไหน N/A/L/P) · AC(ยาก/ง่าย) · AT · PR · UI + ผลกระทบ C/I/A ทั้งระบบเป้าหมายและระบบต่อข้างหลัง
  • ชื่อคะแนน: CVSS-B → BT → BE → BTE (ใส่กลุ่มไหนบ้าง)

L6 · Exploitation Concepts"พิสูจน์ว่าประตูนี้งัดได้จริง"

Exploit = เอาช่องโหว่มาใช้จริงเพื่อ bypass การป้องกัน — แต่ละ OS/service/เวอร์ชันต้องใช้วิธีต่างกัน · เป้าหมายไม่ใช่ "พังให้ได้" แต่คือ พิสูจน์ impact+เข้าใจความลึกของปัญหา เพื่อเขียน report ที่หนักแน่น

Goals 5 ข้อแปลง่ายๆ
Validateช่องโหว่ที่ scanner ว่าใช่ — จริงป่าว
Assess Impactถ้าโจรใช้ จะเจ็บแค่ไหน
Gain Accessได้ shell/บัญชี/ข้อมูลโดยไม่อนุญาต
Elevate Privilegesจากพนักงาน → เจ้าของบ้าน (root/SYSTEM)
Persistenceล็อกกุญแจสำรองไว้กลับมาใหม่ได้
4 ช่วงของ Exploitation Phase
  1. Prep: คัดช่องโหว่ที่คุ้ม (severity/impact/exploitability) → เตรียม/custom exploit
  2. Execute: ยิง → ได้ foothold แรก (shell/บัญชี/คุมเว็บ)
  3. Post-Exploit: privesc → สำรวจข้างใน (sw/network/security config) → ดึงข้อมูลสำคัญ → ฝัง persistence
  4. Cleanup+Docs: ลบร่องรอย + จดทุกอย่างลง report (โจทย์จริงคือ report!)
Metasploit = ชุดเครื่องมือเจาะแบบต่อชิ้น
  • Modules 7: Exploits(ลูกศร) · Payloads(ดินระเบิดปลายทาง: reverse/meterpreter) · Encoders(ห่อหุ้มหลบ AV/IDS) · Auxiliary(สแกน/fuzz/brute ไม่มี payload) · NOP(stuffer) · Post(privesc/เก็บ creds หลังเจาะ) · Evasion(หลบ EDR)
  • สถาปัตยกรรม: Rex(ซ็อกเก็ตพื้นฐาน) → MSF Core(จัดการ session/UI/module) → MSF Base(API ให้ msfconsole ใช้) — UI: msfconsole(CLI)/Armitage(GUI)
  • Reverse vs Bind shell (ออกสอบ): Bind = เราโทรเข้า target (target เปิด port รอ) · Reverse = target โทรกลับมาหาเรา (ผ่าน NAT/FW ได้, นิยมกว่า)
  • Connection Auto/Bind/Reverse: auto เลือกให้เองตามสถานการณ์ NAT
สะพานไป L7: พอเจาะได้ root → ดึง /etc/shadow (รายการ hash รหัสผ่าน) ออกมา → ส่งต่อ John/Hashcat ถอด = ยึดบัญชีทั้งเครื่อง (Post-Exploitation ต่อเนื่อง)
