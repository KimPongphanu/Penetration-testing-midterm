L4 · Enumeration & Service Discoveryเจาะลึกจากผล Scan

Enumeration: ดึง detail เชิงลึกจาก services/ports ที่เปิด — valid usernames, machine/share/directory names, configs, hidden paths ต้องใช้ time + patience ทำ manual หรือ automated แต่ต้อง thorough

  • เทคนิคยอดฮิต: Email IDs/Usernames (→ brute-force) · Default passwords (ระบบตั้งค่าไม่ปลอดภัย) · DNS zone transfer (เปิด topology)
  • Active scanning = ส่ง request วิเคราะห์ response (พบครบแต่ noisy/disruptive) vs Passive = ฟัง traffic เงียบแต่ coverage น้อย
  • Ports น่า enum: FTP21 SSH22 SMTP25 HTTP80 POP3 110 IMAP143 SNMP161 NetBIOS 137–139 SMB445 HTTPS443

RPC / NFS (TCP 111, UDP/TCP 2049)

UNIX เปิด TCP 111 = RPC portmapper · rpcinfo -p <IP> → program/version/port (portmapper, nfs, mountd) · showmount -e <IP> → NFS exports (เช่น share "/" root!) · scanner ส่ง NULL commands ไป RPC-bound ports เดา function ได้

Web application enum (80/443)
  • nmap -sV --script=http-enum <IP> brute paths จาก list รู้จัก → /phpMyAdmin/, /phpinfo.php, Apache/Tomcat default manager
  • nikto -h <IP> open-source web vuln scanner — misconfig + risky files
Fingerprint เพิ่ม

nmap -sC <IP> = รัน common NSE ตามพอร์ตที่เปิด → enum + fingerprint apps/OS ได้ทันที

Lab steps
  1. nmap -sV -p 139,445 <IP> + smbclient -L \\<IP>
  2. enum4linux -a <IP> users/groups/OS
  3. rpcinfo -p <IP> + showmount -e <IP>
  4. nmap -p 80,443 --script http-enum <IP> → hidden paths
  5. nikto -h <IP> web vulns

L5 · Vulnerability AssessmentPTES: Vulnerability Analysis

VA = identify / classify / prioritize ช่องโหว่บน systems/networks/software เทียบ known DB — focus discovery & evaluation ไม่ใช่ break-in · ประเมิน detection/response ของ common attacks (DoS, MITM, SQL Injection, Network Intrusion)

VA vs PT: VA เช็ค known vulnerabilities (กว้าง) — PT เจาะผ่าน defenses พิสูจน์ impact (ลึก) — methods คล้ายแต่ objective ต่าง ใช้คู่กันไม่แทนกัน
ชนิดของ Vulnerability
  • Technological: flaw ใน software/tech (bug ใน app X → control system Y ได้)
  • Configuration: ตั้งค่าผิด (เปิด RDP port บน firewall ของ AD server)
  • Policy: ไม่มี/ไม่ทำตาม policy (ประตู data center ไม่ล็อก)
VA management tasks / analyzers
  • Scan environment → generate full report → analyze → prioritize by risk → ตัด false positives → report real vulns
  • Analyzer: scan+enumerate พร้อมกันจาก interface เดียว จัด risk ตาม OS/service/app version เทียบ DB อัปเดตล่าสุด
  • Scanner ทำงาน: probe ส่งข้อมูล → วิเคราะห์ fingerprint response → ports/services/OS/vulns
  • Pros: automation (recon/port/service/version detection) เร็วกว่า manual · Cons: loud (traffic โดน detect ง่าย), false positives + false negatives
  • แนวทาง: automated (Nessus/OpenVAS เทียบ DB) + manual deep-dive ให้ครบถ้วน
Riskความหมายการจัดการ
Highcritical vulns โจมตีง่าย → control เต็มระบบ/compromise ข้อมูลแก้ทันที (immediate)
Mediumsevere แต่ exploit ซับซ้อน / access จำกัดระยะสั้น
Lowmoderate — เปิดข้อมูลให้ attacker ใช้ต่อmitigate ตามสมควร ไม่ด่วน
VA steps (7)
  1. เช็ค target alive ด้วย ICMP ping
  2. Scan ports แบบ stealth + ทดสอบด้วย harmful information
  3. ระบุ potential vulns + generate report ด้วย network vuln scanner
  4. Classify vulns + build responses (บาง response non-actionable จาก complexity/risk)
  5. Classify key assets เป็น hierarchy → drive risk management
  6. Follow-up docs/reports/consulting หลัง assessment
  7. Initiate ongoing security effort (แผนรักษาความปลอดภัยต่อเนื่อง)
CVSS v4.0 (จัดการโดย FIRST)
  • 4 metric groups: Base / Threat / Environmental / Supplemental · Nomenclature: CVSS-B, CVSS-BT, CVSS-BE, CVSS-BTE (เน้น actual risk มากกว่า theoretical severity)
  • Base: Exploitability — Attack Vector AV: Network/Adjacent/Local/Physical · Attack Complexity AC: Low/High · Attack Requirements AT: None/Present · Privileges Required PR · User Interaction UI · Impact — VC/VI/VA (vulnerable sys) + SC/SI/SA (subsequent sys)
  • Environmental: Security Requirements CR/IR/AR (Low/Med/High ตาม CIA) + Modified impact metrics MVC…MSA (segmentation ลด blast radius)
  • Supplemental (ไม่กระทบ score แต่ให้ context): Safety S(P/N/X) · Automatable AU(Y/N "wormable") · Recovery R(A/U/I) · Value Density V(D/C) · Response Effort RE(L/M/H) · Provider Urgency U(Clear/Green/Amber/Red)

CVE / CWE / KEV / SSVC
  • CVE (MITRE): ID เฉพาะ เช่น CVE-2011-2523 (vsftpd 2.3.4 backdoor), CVE-2014-3566 (POODLE = Padding Oracle On Downgraded Legacy Encryption, SSLv3), CVE-2012-1823 (PHP-CGI RCE) — ค้นที่ cve.org / cve.mitre.org
  • CWE: community list ของ weaknesses = root causes ของ CVE records
  • KEV: Known Exploited Vulnerabilities — actively exploited จริงใน wild ต้องรีบแก้ (record มี catalog link + date added)
  • SSVC: วิเคราะห์ตาม exploitation status / safety impact / prevalence ในระบบ
  • Lab: คำนวณ CVSS v4 ของ CVE-2011-2523 (Base + VS/SS metrics SC/SI/SA = None)
VA report components

Executive Summary (scope/method/key findings/severity/impact/recs) · Introduction (purpose/scope/methodology/audience) · Findings (ID/desc/location/impact/evidence-PoC/risk แยก Critical→Low) · Risk Assessment (posture/prioritization/critical assets) · Recommendations (actionable, prioritized remediation, cost-benefit) · Appendix (scans/logs/screenshots/diagrams) — Tips: ภาษาชัด ไม่ใช้ jargon · ใช้กราฟ/ตาราง · focus high-severity · rec ที่ทำได้จริง

L5 · Tools & LabNSE → Nessus → OWASP ZAP
1) Nmap NSE scripts
  • Scripts เขียนด้วย Lua อยู่ /usr/share/nmap/scripts · อัปเดต DB: sudo nmap --script-updatedb
  • nmap --script vuln <Target_IP> → เจอ ftp-vsftpd-backdoor (CVE-2011-2523), ssl-poodle (CVE-2014-3566)
  • nmap --script ftp-anon <Target_IP> เช็ค anonymous FTP login
  • nmap --script ssh-auth-methods.nse <Target_IP> ตรวจ auth methods ที่เปิด
2) Tenable Nessus (host/network scanner)
  1. Register Nessus Essentials (ฟรี ≤16 IP — activation code ส่งเข้า email) จาก tenable.com (รองรับ Mac/Ubuntu/AARCH64)
  2. Install: sudo dpkg -i Nessus-10.9.1-debian10_amd64.deb
  3. Start service: sudo systemctl start nessusd (/bin/systemctl start nessusd.service)
  4. Browser https://localhost:8834 → register + activate → ตั้ง username/password (เช่น nessus / kali)
  5. New Scan → template Basic Network Scan → ตั้งชื่อ scan + targets: IP เดี่ยว / comma-separated หลาย IP / range 192.168.1.1-192.168.1.128 / subnet 192.168.1.0/24 / domain target.com → (optional) Schedule scan → Save → Launch
  6. วิเคราะห์: แท็บ Vulnerabilities → กรอง CRITICAL/HIGH → อ่าน Description + Solution (Remediation steps) ของแต่ละ plugin

จุดเด่น: DB vuln ใหญ่กว่า OpenVAS · local/remote/credentialed scans + social engineering checks · รายงานละเอียด (desc/severity/remediation/plugin) · compliance auditing

3) OWASP ZAP (Zed Attack Proxy) — webapp
  1. Install: sudo apt update → sudo apt install zaproxy (หรือโหลด installer จาก zaproxy.org)
  2. Run zaproxy → เลือก Standard UI → Persist Session กำหนดไฟล์ .zap (เช่น my_metasploitable_session.zap)
  3. Firefox → Settings → Network Settings → Manual proxy: HTTP + SSL = 127.0.0.1:8080 ✓ "Also use this proxy for HTTPS"
  4. ติดตั้ง CA certificate: browse http://zap/ → download Root CA cert → Import ใน browser (จำเป็นสำหรับ HTTPS)
  5. เปิด http://<Target_IP>/ ผ่าน proxy → คลิกขวา host ใน Sites tree → Attack → Active Scan (หรือใช้ Quick Start → Automated Scan กรอก URL ตรงๆ)
  6. ดูผลที่แท็บ Alerts: Remote Code Execution (CVE-2012-1823), Path Traversal, Missing Security Headers …
  7. Report menu → Generate HTML report ส่งออกได้

L6 · Exploitation (Metasploit)PTES: Exploitation — พิสูจน์ว่าเจาะได้จริง

Exploit = bypass security flaw/control; vector ต่างกันตาม OS/service/process ของเป้าหมาย เป้าปลายทางคือ unauthorized access / control / information — พิสูจน์ potential impact + ความลึกของ flaw

Goals & key activities
  • Goals: Validate vulns exploitable · Assess impact/damage · Gain unauthorized access · Elevate privileges → admin/root/SYSTEM · Establish persistence
  • Activities: PoC (script/tool พิสูจน์) · Exploit development custom · Gaining access (shell/privesc/exfil) · Lateral movement ขยาย footprint
Steps (4)
  1. Preparation/Planning: เลือก vulns promising (severity/impact/exploitability) เตรียม/customize exploit
  2. Execution: launch exploit → initial foothold (account/shell/webapp control)
  3. Post-Exploitation: privesc www-data→root/SYSTEM · system enum (sw, net config, sec settings) · data exfiltration · persistence (backdoor/accounts/config)
  4. Cleanup & Docs: ลบ artifacts กัน detect + document findings
Tools / techniques

Frameworks: Metasploit, Core Impact, Canvas (prebuilt) · custom exploits · manual (code injection, param manipulation) · social engineering (phishing, pretexting)

Metasploit Framework (Ruby)
  • Pentest system + platform พัฒนา tools — module launcher: configure exploit → launch; สำเร็จ → payload runs → shell interact · hundreds exploits/dozens payloads
  • vs Scanner: scanner passive เช็ค/report เท่านั้น · Metasploit = actual exploitation tool
  • Architecture: Rex (sockets TCP/UDP/SSL/HTTP/SMB) → MSF Core (events/sessions/UI/module mgmt) → MSF Base (msfconsole APIs) · UIs: msfcli / msfconsole / Armitage(web GUI)
