L10 · Kioptrix Level 1 — Lab Stepsโจทย์แนว: เติมคำสั่งหาช่องโหว่/เจาะเครื่อง
  1. Import VM: แก้ config bridged → nat → save → ดับเบิลคลิกเปิดเครื่อง
  2. หา IP เป้าหมาย: sudo arp-scan -l หรือ sudo netdiscover -P -r 192.168.74.0/24
  3. สแกนช่องโหว่ด้วย NSE: nmap --script vuln 192.168.74.130
  4. เช็ค FTP anonymous: nmap --script ftp-anon 192.168.74.130 · SSH methods: nmap --script ssh-auth-methods.nse <IP>
  5. หา hidden path บนเว็บ: gobuster dir -u http://192.168.74.130/ -w /usr/share/wordlists/dirb/common.txt
  6. Enum จาก SMB/NetBIOS: enum4linux -a 192.168.74.130
  7. สแกนเว็บละเอียด: nikto -h http://192.168.74.130
  8. Exploit: msfconsole → search smb version → set rhost 192.168.74.130 → run
คำสั่งวัตถุประสงค์ (ออกสอบบ่อย)
arp-scan -lสแกนหาอุปกรณ์ทั้ง local network ผ่าน ARP
netdiscover -P -r …-P = โหมด passive · -r = ระบุช่วง IP ที่ค้น
--script vulnรันชุด NSE ตรวจช่องโหว่ของบริการที่พบ
--script ftp-anonเช็คว่า FTP เปิด anonymous login หรือไม่
gobuster dir -u … -w …dir = โหมดบรูท directory/file · -u = URL เป้า · -w = wordlist (หา /admin, /backup.zip ที่ไม่ถูก link)
enum4linux -aenumerate ครบ — users / groups / shares / OS จาก SMB+NetBIOS
nikto -h …web vuln scanner — -h ระบุ host/URL เป้าหมาย
search / set rhost / runmsfconsole: หา module / กำหนดเครื่องเป้าหมาย / เริ่มโจมตี

⚠️ กับดักจากสไลด์: ตอน exploit SMB เครื่อง Kioptrix — msf ล้มเหลวเพราะ "ขาด payload" → ต้องเพิ่ม payload ให้ตรงกับเป้า (เช่น set PAYLOAD หรือเปลี่ยน module) ไม่งั้นยิงไม่เข้า

L10 · Penetration Testing Report — Q&Aโจทย์แนว: อธิบาย/เรียงขั้นตอน
คำถามแนวสอบคำตอบสั้น
เก็บเอกสาร 5 ขั้นตอน?1) Project folder (ชื่อลูกค้า · External/Internal · logbook · reports แยกตาม tool · template — เก็บในที่เข้ารหัส) 2) Logbook จดทุกวัน ณ เวลาที่ทำ 3) Capture images/video ตั้งชื่อ # Exploit – Apache Webserver.jpg 4) Findings chart (high risk + exploit ง่ายสุดก่อน) 5) Template
โครงรายงานหลักมีอะไรบ้าง?Executive Summary → Methodology → Findings (+PoC) → Recommendations → Appendices
Executive Summary เขียนให้ใคร มีอะไร?ผู้บริหารไม่เทคนิค — Engagement objectives · Scope · Key findings · Overall security posture · Recommendations
Findings ต้องมีอะไร?CVE ID · Description · Severity (high/med/low/info) · Evidence — พร้อม Impact Assessment + Risk Assessment
PoC คืออะไร มีกี่รูปแบบ?หลักฐานพิสูจน์ว่าโจมตีได้จริง: exploit code · manual demonstration · screenshots/logs
รายงาน 3 ประเภท ต่างกันยังไง?Executive (C-level: risk classification/statistics/risk matrix) · Management (compliance/assumptions/change+config mgmt) · Technical (request-response data/vulnerability map/exploit map/best practices)
ทำไมต้อง reproducible?ลูกค้าจะทำตาม steps ของเราเพื่อยืนยันว่าแก้ได้จริง + ใช้ trace เหตุการณ์ระหว่าง test window · false negative = ขายความมั่นใจปลอม
Post-testing procedures?Remediation ตาม recommendations · ติดตั้ง IDS/IPS-firewall-AV · divide-and-conquer network zones · เสริม secure coding + code audit · อัปเดตระบบ (CIA) · ตรวจยืนยันโซลูชันทั้งหมด

💡 จำ: ไม่มีรายงาน = ไม่มีผลงาน · ทุก input/output ของเครื่องมือต้องถูกบันทึก · รายงานต้องตรงกลุ่มผู้อ่าน (ผู้บริหาร ≠ ทีมเทคนิค)

L11 · Incident Response & Risk Management — Q&Aทฤษฎีล้วน — ท่องตัวเลข + วงจร
คำถามแนวสอบคำตอบสั้น
Risk Management คือ? (proactive/reactive)Proactive — คาดการณ์ก่อนเกิด: Identify → Assess → Mitigate → Monitor (ลดโอกาส + ผลกระทบ)
Incident Response คือ?Reactive — หลังเกิดเหตุ: ลดความเสียหาย → ฟื้นระบบ → เรียนรู้
Incident (FISMA 2014) นิยาม?เหตุที่คุกคาม/ใกล้คุกคาม C-I-A ของข้อมูลหรือระบบ โดยไม่มีอำนาจตามกฎหมาย หรือละเมิดกฎหมาย/นโยบายความปลอดภัย
ตัวอย่าง incident?Malicious code (ransomware) · DoS · Phishing · Unauthorized access · Insider · Data breach · Targeted attack
IR Life Cycle 4 เฟส?Preparation → Detection & Analysis → Containment/Eradication/Recovery → Post-Incident (รุ่นใหม่ SP 800-61r3 อิง CSF 2.0 + continuous improvement กลางวงจร)
CSF 2.0 6 Functions?Govern → Identify → Protect → Detect → Respond → Recover (Govern เพิ่มใหม่ใน 2.0)
IR Plan ขั้นต่ำต้องมี?Key contacts (≥2 ช่องทาง/≥2 คน) · Escalation criteria · Flowchart ครบ life-cycle · Conference number · Legal/regulatory guidance
บทบาทในทีม IR?Incident handlers · Leadership · Technology · Legal · PR/Media · HR · Physical security · Asset owners
IR vs IM?IM ครอบทุกขั้น — สื่อสาร/จัดการสื่อ/escalate/report ให้เป็นหนึ่งเดียว · IR = งานเทคนิค: triage · วิเคราะห์ · กู้คืน
4 ปัจจัยประเมินระดับภัยคุกคาม?ผลกระทบต่อ (1) อุปกรณ์/ระบบ (2) ข้อมูล (3) แนวโน้มกู้คืน (4) ลูกค้า/ผู้ใช้ → ระดับ: ไม่ร้ายแรง/ร้ายแรง/วิกฤต ก./วิกฤต ข.
มาตรการ 4 ระยะ?Preparation → Detection & Analysis → Containment/Eradication/Recovery → Post-Incident Activity
กฎหมาย/ตัวเลขสำคัญ (ไทย)?Cybersecurity audit ≥ปีละครั้ง + ส่ง NCSA ภายใน 30 วัน · Risk assessment ≥ปีละครั้ง · IRP อัปเดต ≥ปีละครั้ง · พ.ร.บ. ไซเบอร์ 2562 (ม.49 CII / ม.60 ลักษณะภัย) · เอกสาร ก๑/ก๒/หมวด ง
Framework 5 ด้าน (ประกาศฯ)?Identify (Asset · Risk · VAPT · Third-party) · Protect · Detect · Respond · Recover
