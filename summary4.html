L10 · Penetration Testing ReportReporting — เฟสสุดท้ายที่ทำให้งานมีคุณค่า

5 เฟสของ Pentest: Recon → Scanning → Vuln Assessment → Exploitation → Reporting · Post-Engagement: (1) Report Generation — findings + recommendations (2) Remediation — จัดลำดับ + patch (3) Awareness Training (4) Follow-up — re-test + monitoring

ทำไมสำคัญ: ทุก input/output ต้องบันทึกให้ reproducible — ลูกค้าจะทำตามขั้นตอนเราเพื่อยืนยันว่าแก้ได้จริง + ใช้ย้อนรอยเหตุการณ์ระหว่าง test window

ลักษณะรายงานที่ดี
  • Consistency กับสิ่งที่พบจริง · จัดทำดี + สนับสนุน compliance
  • ระบุ: modus operandi ของ attacker · tools/techniques · ช่องโหว่ · วิธีการ exploit ที่พิสูจน์แล้ว
  • ⚠️ False negatives = "ขายความมั่นใจปลอม" — integrity ของข้อมูลทดสอบห้ามมีข้อผิดพลาด
5 ขั้นตอนเก็บเอกสาร
  1. Project folder: ชื่อลูกค้า → External/Internal Hacking → logbook + subfolder phase/tools + reports (แยกตาม tool) + template ใส่ข้อมูลลูกค้า · เก็บในที่เข้ารหัส
  2. Logbook: จดทุกวัน ณ เวลาที่ทำ (กันลืม + copy-paste เข้ารายงานได้)
  3. Capture images/video: จุดสำคัญ (เจอ vuln, เจาะเข้าได้, trophy) — ตั้งชื่อ เช่น # Exploit – Apache Webserver.jpg
  4. Findings chart: สรุปตารางช่องโหว่ — เริ่มจาก high risk + exploit ง่ายสุด
  5. Template: Executive Summary · Methodology · Findings · Recommendations · Appendices

Post-Testing Procedures

Remediation ตาม recommendations (ระวังอย่ากระทบฟังก์ชัน) · ติดตั้ง IDS/IPS, firewall, content protection, AV · Divide-and-conquer zones แยก secure ออกจาก public · เสริมทักษะ secure coding + code audit · อัปเดตระบบสม่ำเสมอ (CIA) · ตรวจยืนยันทุกโซลูชันที่แนะนำ

Lab: Kioptrix Level 1

Import: แก้ config bridged → nat · หา IP: sudo arp-scan -l หรือ sudo netdiscover -P -r 192.168.74.0/24

  1. nmap --script vuln <IP> · nmap --script ftp-anon <IP> · nmap --script ssh-auth-methods.nse <IP>
  2. gobuster dir -u http://<IP>/ -w /usr/share/wordlists/dirb/common.txt — หา hidden paths (/admin, /backup.zip)
  3. enum4linux -a <IP> — users/groups จาก SMB/NetBIOS · nikto -h http://<IP> — web vulns
  4. msfconsole → search smb version → set rhost <IP> → run → ⚠️ สไลด์: exploit ไม่สำเร็จเพราะ ขาด payload — ต้องเลือก payload ให้ตรง

💡 เกร็ด: ทุกคำสั่งใน lab = หลักฐานที่ต้องแคป+จดใน logbook ตั้งแต่ต้น — ถ้าเก็บตอนทำ รายงานจะเสร็จเอง (copy-paste) · ตั้งชื่อไฟล์ S3L10_<รหัส>.pdf

Risk Management (Proactive) vs Incident Response (Reactive)

RM = คาดการณ์+ลดความเสี่ยงก่อนเกิด: Identify (ระบุความเสี่ยง) → Assess (โอกาส×ผลกระทบ) → Mitigate (controls: patch/policy) → Monitor (ติดตามต่อเนื่อง) · IR = รับมือหลังเกิด: ลดความเสียหาย ฟื้นระบบ เรียนรู้

Incident (FISMA 2014)

เหตุที่คุกคาม (หรือใกล้คุกคาม) Confidentiality/Integrity/Availability โดยไม่มีอำนาจตามกฎหมาย หรือละเมิดกฎหมาย/นโยบายความปลอดภัย/นโยบายการใช้งาน

ตัวอย่าง (NCSC): Malicious code (ransomware) · DoS · Phishing · Unauthorized access · Insider · Data breach · Targeted attack

IR Life Cycle (NIST SP 800-61)
  1. Preparation: แผน + ทีม CIRT/CSIRT + tools
  2. Detection & Analysis: รู้ว่าเกิด + ขอบเขต (วิเคราะห์เทคนิค → social media)
  3. Containment, Eradication & Recovery: บล็อก/แยกเครื่อง/reset บัญชี (+media handling) · eradicated = ถอนราก · recover = business as usual
  4. Post-Incident: บันทึก + lessons learned

r3 update: โมเดลใหม่ตาม CSF 2.0 — continuous improvement อยู่กลางวงจร (ID.IM) · บทเรียนจากทุก Function ป้อนกลับไปปรับปรุงทั้งหมด

Challenges: ไม่มีสองเหตุการณ์เหมือนกัน · ต้องใช้ People+Process+Technology ร่วมกัน · วางแผนล่วงหน้า = ตัวกำหนดผลลัพธ์

IR vs IM: IM ครอบทุกขั้น — สื่อสาร/จัดการสื่อ/escalate/รายงาน ให้ response ทั้งหมดเป็นหนึ่งเดียว · IR = งานเทคนิค: triage, วิเคราะห์ลึก, กู้คืน

IR Plan ขั้นต่ำ + Post-Incident
  • Key contacts: IR team, IT, Mgmt, Legal, PR, HR, Insurance — ≥2 ช่องทาง, ≥2 คน/กลุ่ม
  • Escalation criteria (severity → เร็วแค่ไหน/ถึงใคร) · Flowchart ครบ life-cycle · Conference number · Legal guidance
  • บทเรียนควรแชร์ทันทีที่พบ ไม่รอจบ recovery · ปรับปรุงต่อเนื่องเสมอ
  • Post-incident review: lessons from incident (ป้องกัน/ตรวจจับเร็วขึ้นได้ไหม, tactical vs strategic, data ที่ขาด) + lessons from response (สำเร็จไหม, จุดที่ทำได้ดีกว่า, data ที่ไม่มีใช้)

Framework 5 ด้าน: Identify (Asset mgmt · Risk assessment · VAPT · Third-party) · Protect (Access control · Hardening · Remote access · Removable media · Awareness · Info sharing) · Detect (Monitoring) · Respond (IRP · Crisis comms · Exercise) · Recover (Resilience)

ระดับภัยคุกคาม: ไม่ร้ายแรง / ร้ายแรง / วิกฤติ ก / วิกฤติ ข — ประเมินจาก 4 ปัจจัย: (๑) ผลกระทบต่ออุปกรณ์/ระบบ (๒) ผลกระทบต่อข้อมูล (๓) แนวโน้มกู้คืน (๔) ผลกระทบต่อลูกค้า/ผู้ใช้

มาตรการ 4 ระยะ: Preparation → Detection & Analysis → Containment/Eradication/Recovery → Post-Incident · พ.ร.บ. ไซเบอร์ ๒๕๖๒ มาตรา ๔๙ (CII) / ๖๐ (ลักษณะภัย) · เอกสาร ก๑ (ข้อมูลที่ต้องแจ้ง) ก๒ (แบบรายงาน) หมวด ง (รายละเอียดภัย)
